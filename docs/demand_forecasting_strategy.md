# 需量预测算法设计方案

## 目标与边界

需量预测的目标不是单纯预测负荷曲线，而是服务于用户侧储能调度、需量电费控制和月度运营决策。后续算法实现应围绕最大需量、突破风险和调度收益构建，而不是只追求 `P_load(t)` 的逐点误差最小。

核心对象如下：

| 对象 | 含义 | 用途 |
|------|------|------|
| `P_load(t)` | 用户侧负荷功率，通常为 5 分钟或 15 分钟粒度 | 负荷预测基础序列 |
| `P_grid(t)` | 进线功率，通常为 `P_load(t) + P_charge(t) - P_discharge(t)` | 需量计量与电费核算对象 |
| `D_15min(t)` | 对 `P_grid(t)` 按计量窗口取平均后的需量序列 | 判断是否突破需量上限 |
| `D_month_max` | 结算月内已经发生或预测的最大需量 | 需量电费和月度风险核心变量 |
| `D_current_max` | 本月截至当前已经发生的最大需量 | 月中调整上限的不可逆基准 |
| `D_cap` | EMS 或人工策略允许的进线需量上限 | 储能调度约束或建议值 |
| `D_risk` | 未来 `D_15min(t)` 或 `D_month_max` 突破 `D_cap` 的概率 | 风险约束和告警依据 |

需量窗口口径必须来自合同、计量规则或项目配置。当前项目的 `src/ele_trading/demand` 已支持固定窗口和滑动窗口最大需量计算；后续预测方案只应调用或复用该口径，不应在模型内部硬编码“15 分钟滑动窗口”等业务假设。若合同采用固定 15 分钟、滑动 15 分钟、30 分钟或其他口径，应由配置显式决定。

## 规则输入

以下规则不是预测模型参数，而是调度和收益评估的外部输入：

- 结算周期：通常按月核算，但必须以合同或当地电价规则为准。
- 需量计量对象：应明确是总进线、分变压器进线、园区汇总，还是某个计量点。
- 计量窗口：固定窗口或滑动窗口，窗口长度和采样粒度必须一致。
- 需量电价：`demand_charge_rate`，单位通常为元/kW/月。
- 合同需量和允许调整规则：是否允许月中调整、调整次数、生效延迟、是否需要人工确认。
- 突破后的成本规则：突破是否影响整月结算，是否存在阶梯、罚金或追补。
- 储能执行边界：SOC 上下限、可用功率、效率、循环成本、辅机自用电和设备不可用时段。
- 分时电价和购售电规则：影响储能套利收益，不应与需量电费混在同一个不可解释指标里。

不确定的规则应保留为配置或待确认项，不能在算法中默认拍板。

## 分层策略

### 月末：预测下月需量区间

月末预测用于合同需量、下月初始 `D_cap` 和运营风险准备。此阶段不应依赖整月 5 分钟点预测直接做强优化，因为远期逐点误差会在最大值聚合时被放大。

推荐输入：

- 历史 `D_month_max`、日最大需量、峰值出现日期和时段。
- 同季节、同月份、同星期、节假日和特殊运营日标签。
- 天气、温湿度、PUE、业务增长、IT 负载计划、检修或扩容计划。
- 储能可用率、历史控需失败记录、EMS 上限调整记录。

推荐输出：

- 下月 `D_month_max` 的 `P50/P75/P90/P95` 分位预测。
- 保守、推荐、激进三档 `D_cap` 候选。
- 每档 `D_cap` 下的突破概率、预计需量电费和运营风险说明。

推荐方法：

- v1 使用历史同季节分位数、同比/环比修正和规则模型。
- 数据积累后使用 LightGBM/XGBoost 分位回归预测日最大需量，再聚合为月度最大需量分布。
- 对月度最大值应单独回测，不能只用普通负荷点预测误差替代。

### 月初：确定本月初始 `D_cap`

月初策略用于把月末先验修正为本月可执行上限。相比月末，月初可以引入本月已发生负荷、最新天气、PUE 和运营计划。

推荐逻辑：

1. 读取月末 `D_month_max` 分位预测作为先验。
2. 用本月已发生的 `D_current_max`、天气和运营信息更新剩余月份情景。
3. 生成剩余月份 `P50/P90/P95` 情景。
4. 枚举多个候选 `D_cap`。
5. 对每个 `D_cap` 做整月或剩余月份储能调度仿真。
6. 选择净收益最高且 `P90/P95` 风险可接受的初始上限。

收益评估至少拆成：

```text
净收益 =
  电度成本节省
  - 需量电费增加
  - 储能循环成本
  - 效率损耗成本
  - 辅机和冷却自用电成本
  - 突破风险折价
```

月初不应只使用一条点预测曲线决定 `D_cap`。推荐用 `P50` 测算收益，用 `P90/P95` 校验控需风险。

### 月中：动态判断是否调整 `D_cap`

月中策略用于判断维持、提高或收紧当前 `D_cap`。此时 `D_current_max` 已经发生，若需量电费按月最大值结算，已经发生的高峰通常不可逆，因此月中调整必须按边际收益决策。

推荐输入：

- 本月已发生 `D_current_max` 和对应时间。
- 当前 EMS `D_cap`、实际执行偏差和生效延迟。
- 剩余月份 `P50/P90/P95` 负荷和需量预测。
- 剩余月份分时电价、SOC 初值、储能可用功率和容量。
- 合同需量、突破成本、人工确认流程和风险阈值。

推荐决策公式：

```text
净收益增量 =
  剩余月份电度套利增量
  - 新增需量电费
  - 储能循环成本增量
  - 辅机损耗成本增量
  - 预测不确定性风险折价
```

只有当 `净收益增量` 大于安全阈值，且 `P90/P95` 情景下突破风险可接受时，才建议提高 `D_cap`。

月中策略分三类：

- 低风险维持：当前 `D_cap` 足够，继续控需。
- 收益型抬升：放宽 `D_cap` 后，剩余月份套利收益显著超过新增需量成本。
- 防守型抬升：自然负荷未来突破概率高，提前抬升可减少被动突破后的调度损失。

不应只因为某一天谷段充不满就抬升 `D_cap`。正确判断依据是剩余月份边际套利和新增需量成本。

### 每日：生成 24-48 小时调度计划

每日预测用于生成日前或日内储能计划。预测粒度应不低于结算窗口要求；如果底层数据为 5 分钟，需量计算应显式转换为合同约定的固定或滑动窗口。

推荐输入：

- 最近 1 天、7 天、同星期几、同季节负荷曲线。
- 天气、PUE、节假日、业务负载计划和异常运营标记。
- 当前 SOC、储能可用容量、功率限制和设备状态。
- 当前 `D_current_max`、目标 `D_cap`、分时电价和购售电规则。

推荐输出：

- 未来 24-48 小时 `P_load(t)` 的点预测和 `P50/P90/P95` 分位预测。
- 调度建议：`P_charge(t)`、`P_discharge(t)`、SOC 曲线。
- 预计 `P_grid(t)`、`D_15min(t)` 和最大预计需量。
- 是否触碰 `D_cap`、预计收益、备用 SOC 和风险告警。

每日优化目标是降低综合用能成本，同时约束 `D_15min(t)` 不超过可接受上限。预测误差较大时，应保留安全裕度；安全裕度不应固定写死为 3%-5%，而应通过历史回测按站点和季节校准。

### 每小时：滚动修正实时执行

小时级预测用于滚动修正，不负责重新制定月度策略。重点是滑窗需量风险、执行安全和短时预测稳定性。

推荐输入：

- 当前 SOC 和储能可用状态。
- 当前计量窗口内已经发生的 `P_grid(t)`。
- 当前 `D_current_max` 和 `D_cap`。
- 未来 1-4 小时短时 `P_load(t)` 分位预测。
- 当前电价、设备状态、EMS 执行反馈和人工锁定指令。

推荐逻辑：

```text
如果未来 15-60 分钟存在突破 D_cap 风险：
    降低充电功率或转为放电
如果负荷低且当前计量窗口安全：
    允许充电，但不得推高 D_15min(t) 到风险区间
如果峰段且 SOC 足够：
    同时按电价和 D_risk 决定放电功率
如果预测不确定或设备状态异常：
    保留 SOC 安全余量，降低激进套利动作
```

小时级调度建议使用 MPC：每次重算未来 1-4 小时，但只执行最近一个 5 分钟或 15 分钟控制量。后续周期应根据实测 `P_grid(t)` 和 SOC 重新优化。

## 算法路线

### v1：规则分位数 + GBDT 分位回归

第一版应优先使用可解释、易回测的模型：

- 历史同类日分位数：按月份、星期、节假日、温度区间和业务标签筛选相似日。
- LightGBM/XGBoost 分位回归：分别训练 `P50/P75/P90/P95`，目标是预测日最大需量或未来窗口负荷分位。
- 残差校准：按月份、小时、温度区间和负荷水平校准分位覆盖率。

LightGBM 的 `quantile` objective 可直接用于分位预测。XGBoost 可采用 quantile loss 或自定义目标，若实现成本较高，第一版优先 LightGBM。

### v2：概率预测基线

数据稳定后可引入成熟时间序列库作为对照基线：

- Darts：适合统一传统模型、机器学习模型和深度学习模型的时间序列实验。
- GluonTS：适合概率预测、分布输出和场景采样。
- NeuralForecast：适合深度学习时间序列模型，并可参考需求峰值识别类示例组织特征和评估。

这些库不应直接替代业务决策层。它们只负责生成概率预测或场景，`D_cap` 决策仍应由收益仿真和风险约束决定。

### v3：预测-仿真-优化闭环

成熟版本应形成闭环：

```text
历史数据清洗
→ 分位负荷预测
→ D_15min(t) 和 D_month_max 推导
→ D_cap 候选枚举
→ 储能调度仿真
→ 成本收益拆分
→ 回测校准 P50/P90/P95
→ 输出可执行策略
```

回测结果应反向校准安全裕度和风险阈值。若某站点在 `P90` 下仍频繁突破，说明分位预测没有校准好，不能简单提高 `D_cap` 掩盖预测问题。

## 评价指标

后续实现不能只输出普通负荷预测误差。至少应分四类评价。

| 类别 | 指标 | 说明 |
|------|------|------|
| 负荷点预测 | MAE、RMSE、MAPE、sMAPE | 衡量 `P_load(t)` 基础预测能力 |
| 峰值预测 | `D_month_max` 误差、Top-k 峰时段召回率、突破漏报率 | 衡量控需场景真正关心的高峰能力 |
| 概率预测 | pinball loss、分位覆盖率、`P90/P95` 校准误差、CRPS | 衡量分位预测是否可信 |
| 调度收益 | 电度成本、需量成本、循环成本、突破风险成本、净收益 | 衡量预测用于调度后的实际价值 |

验收时应优先看峰值预测和调度收益。若 MAE 很低但月最大需量漏报，模型仍然不适合控需。

## 建议实现接口草案

本节只定义后续代码实现的建议数据契约，不表示当前项目已经存在这些接口。

### 输入数据表

| 字段 | 含义 |
|------|------|
| `timestamp` | 时间戳，必须可转为连续时间索引 |
| `load_kw` | 用户侧负荷功率 |
| `grid_kw` | 实测进线功率，可选；有储能历史时用于回测 |
| `temperature` / `humidity` | 天气特征，可选 |

| `soc` | 储能 SOC，实时或回测场景使用 |

| 字段 | 含义 |
|------|------|
| `timestamp` | 预测时间戳 |

| `load_p90_kw` | `P_load(t)` P90 预测 |
| `load_p95_kw` | `P_load(t)` P95 预测 |

| `demand_p90_kw` | 按计量口径推导的 `D_15min(t)` P90 |
| `demand_p95_kw` | 按计量口径推导的 `D_15min(t)` P95 |
| `risk_score` | 未来突破 `D_cap` 的风险评分或概率 |

### `D_cap` 决策输出

| 字段 | 含义 |
|------|------|
| `decision_time` | 决策时间 |

| `D_current_max` | 本月已发生最大需量 |
| `D_cap_recommended` | 推荐上限 |
| `D_cap_conservative` | 保守上限 |
| `D_cap_aggressive` | 激进上限 |
| `expected_energy_cost_delta` | 预计电度成本变化 |

## 第一版落地建议

第一版建议按以下顺序实现：

1. 先复用 `src/ele_trading/demand` 的最大需量口径，确保固定窗口和滑动窗口计算与合同配置一致。
2. 实现历史分位数和 LightGBM 分位回归，输出 `P50/P90/P95`。
3. 建立 `D_cap` 候选枚举和回测框架，收益拆成电度成本、需量成本、循环成本和风险成本。
4. 用每日 24-48 小时预测驱动调度仿真，再用小时级 MPC 做滚动修正。
5. 每次回测同时输出峰值预测指标、概率预测指标和调度收益指标。

- LightGBM Parameters：`objective=quantile` 可用于分位回归，适合作为第一版概率预测基线。<https://lightgbm.readthedocs.io/en/latest/Parameters.html>
- Darts documentation：提供统一时间序列预测接口，可用于传统模型、机器学习模型和概率预测实验。<https://unit8co.github.io/darts/>
- GluonTS documentation：面向概率时间序列建模和预测分布输出。<https://ts.gluon.ai/>
- NeuralForecast demand peaks：可参考其需求峰值识别示例组织峰值相关特征和评估。<https://nixtlaverse.nixtla.io/neuralforecast/docs/use-cases/electricity_peak_forecasting.html>
- 概率预测评价建议采用 pinball loss、分位覆盖率和 CRPS；这些指标用于判断 `P90/P95` 是否可信，而不是只展示点预测误差。

## 待确认问题

- 需量电费是否按本月最大固定窗口、滑动窗口或其他口径的进线需量结算。
- 合同中的 1.1 倍平均进线功率是月平均、日平均还是其他结算周期。
- EMS `D_cap` 调整是否需要人工确认，以及生效延迟是多少。
- 储能冷却和辅机自用电是否已经在历史收益复盘中计入。
- 月中突破后的需量成本是否不可逆，以及是否存在阶梯或罚金规则。
- 当前项目应优先按总进线控需，还是按分变压器、分计量点分别控需。
