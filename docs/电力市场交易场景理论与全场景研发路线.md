# 电力市场交易场景理论、项目能力与全场景研发路线

> 文档性质：业务理论框架、当前实现盘点和研发路线规划  
> 适用范围：`src/ele_trading/` 活动交易算法包及其可恢复的用户侧算法资产  
> 当前依据：项目源码与模块 README；具体市场参数仍以经确认的交易规则为准

## 1. 文档目标

“电力市场交易”不是单一算法或单一业务场景。相同的储能调度模型，可能分别服务于
独立储能现货套利、工商业用户削峰填谷、虚拟电厂聚合交易或电网安全调度；这些场景
虽然共享 SOC、功率平衡等物理约束，但市场主体、可见信息、决策变量、收益口径和结算
责任并不相同。

本文解决三个问题：

1. 建立可用于分类电力市场交易问题的多维理论框架。
2. 判断当前 `ele_trading` 实际覆盖了哪些场景，避免把归档或规划能力描述为活动能力。
3. 规划从当前蒙西储能交易决策原型扩展到“全场景电力市场交易”算法平台的研发路线。

本文所称“全场景”是架构目标，不表示单个版本必须实现全国所有市场规则。实际开发应
选择明确的市场、主体和品种，形成可验证的纵向闭环，再逐步扩展。

## 2. 电力市场交易场景的理论框架

### 2.1 电力交易的基本特征

电力交易与一般商品交易的主要区别是：

- **实时平衡**：发电和用电必须持续平衡，申报计划最终需要落到物理执行。
- **网络约束**：输电容量、节点或分区约束会影响可交易电量和价格。
- **多时间尺度耦合**：年度/月度合约、日前计划、日内调整和实时执行相互影响。
- **资产状态耦合**：储能 SOC、机组启停、水库水位和可控负荷恢复过程具有跨时段状态。
- **预测不确定性**：电价、负荷、风光出力、故障和市场成交均存在不确定性。
- **规则驱动结算**：收益不仅来自成交电量和价格，还受偏差考核、回收、补偿、罚金、
  退化和履约规则影响。

因此，一个完整交易算法通常包含：数据时点控制、预测、场景生成、报价或持仓决策、
物理调度、滚动修正、执行、结算、风险管理和回测，而不只是求解一次优化模型。

### 2.2 场景分类的六个正交维度

#### 维度一：市场主体

| 主体 | 典型资源或责任 | 主要决策 |
|------|----------------|----------|
| 发电企业 | 火电、水电、核电、风电、光伏 | 合约仓位、报量报价、机组组合、偏差控制 |
| 独立储能运营商 | 独立电站、共享储能 | 能量套利、辅助服务、容量分配、退化管理 |
| 售电公司 | 批发采购组合、零售用户组合 | 批零组合、零售定价、负荷预测、偏差管理 |
| 批发用户 | 大工业负荷、直接交易用户 | 合约采购、现货购电、需求响应、风险对冲 |
| 工商业用户 | 表后光伏、储能、可控负荷 | 电费最小化、需量控制、自发自用、需求响应 |
| 虚拟电厂/聚合商 | 分布式电源、储能、负荷、充电设施 | 聚合、可用容量评估、市场报价、内部分摊 |
| 电网/市场运营机构 | 网络、出清规则、辅助服务需求 | 安全约束出清、备用安排、阻塞管理、结算 |

#### 维度二：交易时间尺度

| 时间尺度 | 典型任务 | 对后续阶段的影响 |
|----------|----------|------------------|
| 中长期 | 年度/月度/多日合约、基数与曲线分解 | 形成现货敞口和履约责任 |
| 日前 | 次日分时申报、运行计划、资源预留 | 形成次日基准计划 |
| 日内 | 根据新预测与状态滚动调整 | 减少实时偏差和风险 |
| 实时 | 执行控制、偏差平衡、实时价格结算 | 产生最终物理电量和费用 |
| 辅助服务周期 | 调频、备用、调峰等容量与性能履约 | 占用资源能力并产生额外收益/罚金 |
| 月度/结算周期 | 合同回收、偏差考核、账单核对 | 确认最终损益和风险暴露 |

#### 维度三：交易品种

- 电能量：中长期、日前、日内、实时。
- 辅助服务：调频、备用、调峰、黑启动等。
- 容量或可靠性产品：可用容量、容量补偿或容量市场产品。
- 需求响应：削减、移峰、可中断负荷和负荷聚合产品。
- 环境属性：绿证、碳配额、核证减排量等。
- 金融工具：差价合约、远期、期权及其他风险对冲工具。

不同市场并不一定同时提供全部品种，算法必须由具体规则配置驱动，不能把一个地区的
结算公式硬编码为通用市场模型。

#### 维度四：资产组合和物理层级

- 单资产：单台机组、单座储能、单个风场或光伏电站。
- 场站组合：风光储、火储、水风光等联合资源。
- 用户侧组合：负荷、表后光伏、储能、充电设施和柔性设备。
- 多节点资源：园区、区域或多个并网点，受变压器和线路容量约束。
- 聚合组合：虚拟电厂跨用户、跨场站聚合，并包含内部责任分摊。
- 系统级：市场或电网运营机构执行网络约束出清和安全校核。

#### 维度五：决策类型

| 决策类型 | 核心输出 |
|----------|----------|
| 预测与风险表征 | 点预测、分位数、联合场景、概率和误差诊断 |
| 合约与头寸 | 购买/出售合约量、曲线分解、未对冲敞口 |
| 报量报价 | 数量、价格、分段报价曲线、机会成本 |
| 市场出清 | 成交量、出清价、节点/分区结果、约束影子价格 |
| 物理调度 | 出力、充放电、SOC、启停、负荷调整 |
| 实时控制 | 滚动计划、执行指令、偏差修正和回退策略 |
| 结算风控 | 收益、考核、信用敞口、CVaR、履约和归因 |

#### 维度六：优化目标

- 收益最大化：市场收入减购电、退化、罚金和执行成本。
- 成本最小化：购电费、需量费、燃料费、启停费或综合账单。
- 风险调整收益：期望收益与 CVaR、方差或最坏场景的组合。
- 偏差控制：降低申报与执行偏差，满足履约和考核约束。
- 新能源消纳：降低弃风弃光并满足并网和内部负荷约束。
- 系统安全与社会福利：运营机构的安全约束经济调度或市场出清目标。

### 2.3 一个场景必须由多维组合定义

“储能优化”“光伏预测”或“日前算法”都不是完整场景。完整场景应至少描述为：

> 主体 + 市场/地区 + 时间尺度 + 交易品种 + 资产组合 + 决策目标 + 结算口径

例如：

- 独立储能运营商参与蒙西实时电能量市场，以风险调整后的套利收益最大化，并按单结算
  规则核算收益。
- 工商业用户在固定分时零售电价下调度表后光伏和储能，以购电费、需量费和弃光成本
  之和最小化。
- 虚拟电厂聚合多用户储能参与日前电能量与调频市场，同时优化外部报价和内部资源分配。

这三个场景都涉及储能，但不能共享同一套上层交易契约和结算规则。

## 3. 当前项目的准确定位

### 3.1 总体定位

当前活动 `src/ele_trading/` 更准确地定位为：

> **面向储能或聚合资源的蒙西电力市场单结算交易决策与回测原型。**

它以市场参与方视角串联中长期/月度头寸、次日资源运行、日内滚动、需求响应、单结算
和 walk-forward 回测，并提供预测、联合场景和储能风险优化基础能力。

当前项目不是完整的“发电侧全品种交易系统”，也不是市场运营机构出清系统。活动契约
明确不包含完整的日前财务申报量、分段报价和订单簿；当前日前模块以资源运行计划为主，
日前价格仅作为解释性信号，不进入活动单结算。因此，不能把现有实现描述为已经完成
从报价、出清到执行的全流程市场交易平台。

### 3.2 三类能力的边界

#### A. 活动市场交易主线：`trading` + `optimization`

- 服务对象：独立储能运营商、发电侧资源或聚合资源的市场决策方。
- 核心目标：管理中长期敞口、制定资源运行计划、滚动修正、控制风险并完成结算回测。
- 状态：活动实现，由常规入口和测试覆盖。

#### B. 归档用户侧调度：`user_side_dispatch`

- 服务对象：工商业用户或园区表后资源。
- 核心目标：在固定分时电价下最小化电度费、需量费、弃电成本并提高本地消纳。
- 算法资产：规则法、PuLP MILP、CVXPY、单节点与多节点风光储调度。
- 状态：归档暂存；活动包零引用，不属于当前生产交易 API。
- 与交易的关系：只有在接入需求响应、现货购电、辅助服务或虚拟电厂聚合后，才从单纯
  用能优化进一步成为市场交易资源。

#### C. 平级投资测算：`investment_estimation`

- 服务对象：项目投资方和容量规划人员。
- 核心目标：容量配置、运行收益、IRR/NPV、回收期和资源模拟。
- 状态：独立自包含包，不是实时交易执行引擎，也不反向依赖 `ele_trading`。

## 4. 当前实现程度

状态定义：

- **已实现**：活动代码、入口和常规测试已形成可运行闭环。
- **部分实现**：存在算法或契约，但尚缺真实规则、完整市场流程或生产数据闭环。
- **归档**：源码和归档测试存在，但活动代码不得依赖。
- **未实现**：当前源码没有形成对应能力。

### 4.1 分层能力矩阵

| 能力层 | 实现程度 | 当前实现 | 主要限制 |
|--------|----------|----------|----------|
| 市场/资产数据接入 | 部分实现 | `MarketDataSnapshot`、价格/资产/气象读取、质量检查、as-of 与版本 | 以样例和 CSV/天气适配为主，缺生产市场接口与订单/成交数据 |
| 价格预测 | 部分实现 | seasonal-naive、回归、兼容 ARIMA、统一预测契约 | 工程基线，不代表生产精度 |
| 负荷预测 | 部分实现 | 多层级预测与层级协调 | 尚未形成售电公司用户组合预测闭环 |
| 风光功率预测 | 部分实现 | 风/光物理、统计和外部适配路径 | 需真实场站数据校准 |
| 联合场景 | 已实现（工程基线） | 价格/负荷/风/光联合场景、LHS/MC、相关性、Wasserstein 缩减 | 边际和相关结构仍需真实误差标定 |
| 储能物理内核 | 已实现 | SOC、效率、功率、末端、吞吐量、no-export 等约束 | 当前以单资产储能为活动核心 |
| 确定性储能套利 | 已实现 | 单市场套利基准 | 不等同于可直接提交市场的报价策略 |
| MPC 滚动调度 | 已实现 | 单窗口与滚动 MPC | 主要围绕价格和储能状态 |
| Two-stage + CVaR | 已实现 | 第一阶段决策、场景补救、CVaR 风险目标 | 偏差参数需按真实市场规则标定 |
| 中长期/月度头寸 | 部分实现 | 覆盖结构、月度分解、阶梯和透明量价走廊 | 缺真实订单簿、撮合和合同全生命周期 |
| 日前阶段 | 部分实现 | 次日资源运行计划、联合场景 CVaR、DR 联合优化 | 活动契约无完整财务报价/申报和日前出清 |
| 日内滚动 | 已实现（原型） | 冻结执行前缀、剩余窗口重优化、失败回退 | 缺实时生产指令和执行反馈接口 |
| 需求响应 | 部分实现 | 参与经济性评估、联合优化、履约结算 | 产品规则和资源基线仍需市场化扩展 |
| 蒙西单结算 | 已实现（规则待确认项除外） | 实时电能、中长期差价、回收、DR/退化/执行分项 | `TODO(rule-confirm)` 参数用于生产前必须确认 |
| walk-forward 回测 | 已实现 | 无储能/确定性/风险/oracle 基准，无前瞻约束 | 样例数据不能替代真实策略评估 |
| 用户侧风光储 | 归档 | 单节点、多节点、规则/MILP/CVXPY | 未接入活动交易契约和入口 |
| 投资与容量测算 | 独立实现 | IRR/NPV、容量搜索、资源模拟 | 位于平级包，不是活动交易能力 |

### 4.2 按市场主体的覆盖矩阵

| 市场主体 | 实现程度 | 当前能力 | 主要缺口 |
|----------|----------|----------|----------|
| 独立储能运营商 | 已实现/部分市场化 | 储能套利、MPC、Two-stage + CVaR、中长期头寸、日前运行、日内滚动、单结算和回测 | 缺完整报量报价、成交确认、生产执行和辅助服务联合交易 |
| 发电企业 | 部分实现 | 已有风光预测、联合场景、头寸和运行计划基础 | 活动物理内核仍以储能为主，缺火电启停、水电水位、多场站组合、发电侧报价和偏差责任模型 |
| 售电公司 | 未实现 | 可复用负荷预测、中长期—现货和风险优化基础 | 缺零售合同、用户组合、批零定价、采购组合、偏差归因和用户结算 |
| 批发用户 | 未形成闭环 | 已有负荷预测、需求响应、中长期—现货和用户侧调度算法资产 | 缺直接交易购电合同、现货采购、用电偏差、计量账单和风险对冲契约 |
| 工商业用户 | 归档 | `user_side_dispatch` 保留表后风光储、需量控制和多节点调度算法 | 未接入活动交易契约；固定分时电价下的账单优化不等同于批发市场交易 |
| 虚拟电厂/聚合商 | 未形成闭环 | 可复用分布式用户侧调度、预测、联合场景、储能优化和 DR 能力 | 缺资源注册、聚合能力曲线、对外报价、对内分配、计量校核和收益/偏差分摊 |
| 电网/市场运营机构 | 未实现 | 当前结算和回测可作为参与方视角的市场结果消费端 | 缺网络模型、机组组合、安全约束出清、节点/分区价格、阻塞和市场监管能力 |

主体覆盖结论：当前活动能力最接近**独立储能运营商或拥有储能灵活性的聚合资源参与方**，
并非已经覆盖所有发电企业；工商业用户侧能力仅为归档算法资产，其余主体尚未形成完整
“数据—决策—执行—结算—回测”闭环。

### 4.3 按市场层次和时间尺度的覆盖矩阵

本表描述交易从远期头寸到实时执行及事后结算的纵向层次，不把辅助服务、容量、绿证等
交易品种混入时间尺度。

| 市场层次/时间尺度 | 实现程度 | 当前能力 | 主要缺口 |
|-------------------|----------|----------|----------|
| 年度/中长期 | 部分实现 | 中长期覆盖结构、持仓状态和现货敞口表达 | 缺年度合同全生命周期、真实合同曲线、履约调整和交易对手风险 |
| 月度交易 | 部分实现 | 月度分解、集中竞价阶梯和缺少订单簿时的透明量价走廊 | 缺真实订单簿、撮合、成交回执和合同变更 |
| 日前 | 部分实现 | 次日资源运行计划、联合场景 CVaR 和 DR 联合优化 | 活动契约无完整财务报量报价、分段报价、成交结果和日前出清；日前价格不进入当前单结算 |
| 日内 | 已实现（原型） | 冻结已执行前缀、基于新预测和状态的剩余窗口滚动重优化、失败物理裁剪回退 | 缺真实日内市场订单、成交确认、生产指令和状态反馈接口 |
| 实时 | 部分实现 | 可消费实时价格和实绩电量，执行蒙西实时电能结算并核算偏差相关分项 | 缺实时控制指令、遥测/计量接入、执行确认、自动偏差修正和生产级安全边界 |
| 辅助服务履约周期 | 未实现 | DR 提供了相邻的容量评估与履约经验，但不是调频/备用市场实现 | 缺调频、备用、调峰等容量/里程申报、资源预留、性能评价和结算 |
| 日/月度结算周期 | 已实现（规则待确认项除外） | 蒙西单结算覆盖实时电能、中长期差价、月度回收及 DR/退化/执行分项 | `TODO(rule-confirm)` 参数需确认；缺账单对账、发票、信用和跨产品统一结算 |

层次覆盖结论：当前项目已经形成“中长期/月度头寸 → 次日运行 → 日内滚动 → 实时实绩
结算 → walk-forward 回测”的原型链路，但日前和日内仍偏运行决策，不包含完整的市场
订单与成交过程；实时层具有结算计算，不等于已经实现生产实时控制。

### 4.4 按交易品种的覆盖矩阵

| 交易品种 | 实现程度 | 当前能力 | 主要缺口 |
|----------|----------|----------|----------|
| 电能量 | 部分实现 | 中长期差价、月度头寸、次日运行、日内滚动、实时电能结算和储能套利 | 缺完整报价、成交、订单生命周期和多市场规则适配 |
| 需求响应 | 部分实现 | 参与经济性评估、日前联合优化和履约结算 | 缺市场化基线、资源聚合、产品注册、用户补偿和多产品冲突管理 |
| 辅助服务 | 未实现 | 可复用储能物理、机会成本和滚动调度基础 | 缺调频、备用、调峰、黑启动等产品契约、报价、性能与结算 |
| 容量/可靠性产品 | 未实现 | 投资测算包可提供容量方案，但不构成容量交易 | 缺容量义务、可靠性评估、容量报价和容量补偿/罚金 |
| 绿证/碳等环境属性 | 未实现 | 风光预测可提供物理发电量基础 | 缺属性签发、账户、交易、价格、转移和履约核销模型 |
| 电力金融衍生品 | 未实现 | 当前单结算含中长期差价元素 | 尚未形成远期、差价合约组合、期权、保证金和组合风险系统 |

品种覆盖结论：活动主线集中在**电能量市场**，需求响应仅部分覆盖；辅助服务、容量、
环境属性和金融衍生品均未形成活动交易能力。中长期差价结算元素不能被描述为已经实现
完整的电力金融衍生品交易系统。

## 5. 全场景目标架构

### 5.1 架构原则

1. **市场规则与算法内核分离**：规则、产品和结算参数由市场配置与适配器表达，物理内核
   不硬编码地区规则。
2. **外部交易与内部调度分离**：报价/头寸决定对外责任，资源调度决定如何履约，两者以
   明确契约连接。
3. **计划与实绩分离**：forecast、bid、award、dispatch、metering、settlement 均保留
   issue time、valid time、版本和来源。
4. **主体责任隔离**：发电商、储能、售电公司、用户和聚合商使用不同的业务契约，共享
   经过验证的物理与风险内核，而不是共享所有上层字段。
5. **先纵向闭环、后横向扩展**：每新增一个市场场景，都应包含数据、决策、执行、结算、
   回测和测试，不只新增一个优化函数。
6. **规划与交易分离**：`investment_estimation` 保持独立，向交易层提供资产方案和参数，
   不承担实时执行。

### 5.2 建议分层

```text
外部市场/资产/气象/计量数据
                │
                ▼
数据与时间治理层
市场日历 / 交割时段 / 单位 / as-of / 版本 / 质量
                │
                ▼
预测与不确定性层
价格 / 负荷 / 风光 / 可用率 / 联合场景 / 校准
                │
                ▼
市场与组合决策层
合约头寸 / 报量报价 / 成交结果 / 辅助服务 / 风险预算
                │
                ▼
资源聚合与物理调度层
储能 / 风光 / 火电 / 负荷 / 充电设施 / 多节点约束
                │
                ▼
执行与滚动控制层
日前计划 / 日内重优化 / 实时指令 / 状态反馈 / 回退
                │
                ▼
结算、分摊与风控层
市场结算 / 用户账单 / 聚合内部分摊 / 信用 / 归因 / 回测
```

## 6. 分阶段研发路线

路线按依赖关系排列。不能跳过统一时序和结算基础，直接堆叠新市场算法。

### Phase 0：统一领域契约与市场时序基础

**目标**：建立所有后续市场场景共享但不混淆业务语义的基础层。

**交付物**：

- 市场、主体、账户、资产、并网点、交易产品的稳定标识。
- 市场日历、交易日、交割日、申报窗口、冻结窗口和结算周期。
- 功率/电量/价格/货币统一单位及显式换算。
- `Forecast → Bid → Award → Dispatch → Metering → Settlement` 事件契约。
- 市场规则接口和地区配置边界；蒙西为首个具体实现。
- 从当前 `PositionState`、`OperationalPlan`、`IntradayPlan`、
  `SettlementReport` 到统一契约的兼容策略。

**验收标准**：

- 契约能表达计划、成交和实绩三类电量，不再复用同一字段。
- 所有时序对象通过时区、粒度、as-of、版本和单位校验。
- 现有蒙西回测结果在兼容层下保持基线不变。

### Phase 1：补齐电能量市场交易闭环

**目标**：把当前“头寸 + 运行计划 + 结算”扩展为可表达完整交易责任的闭环。

**交付物**：

- 中长期合同生命周期、曲线分解和履约敞口。
- 日前/日内报量报价契约、分段报价曲线和申报约束。
- 外部成交/出清结果适配器；不在参与方算法里伪造市场出清。
- 报价、成交、运行计划、实时实绩和结算逐项归因。
- 价格接受者和策略报价者两种模式。

**验收标准**：

- 使用同一交易日数据可复现“申报—成交—调度—实绩—结算”全链。
- 回测严格限制每个决策时点可见数据，无未来信息泄露。
- 蒙西规则参数全部确认或明确标注为不可生产使用。

### Phase 2：中长期与现货组合风险管理

**目标**：从固定头寸分解升级为多周期组合决策。

**交付物**：

- 年/月/周/日前多层头寸联动。
- 合同、现货敞口和储能灵活性的联合优化。
- 价格、负荷、风光和成交不确定性的联合风险预算。
- CVaR、压力测试、机会成本和损益归因。

**验收标准**：

- 能比较无对冲、固定覆盖、风险优化三类策略。
- 风险指标使用概率校准和独立样本回测，不只报告样本内目标值。

### Phase 3：辅助服务与电能量联合优化

**目标**：支持储能/发电资源同时参与电能量和调频、备用、调峰等产品。

**交付物**：

- 产品容量、里程、性能、可用率和履约结算契约。
- 多产品容量互斥与 SOC 能量预留约束。
- 电能量机会成本和联合报价。
- 产品级结算、罚金与性能回测。

**验收标准**：

- 同一资源不能重复出售不可同时履约的容量。
- 联合策略与单一电能量策略在相同数据上可复现实证比较。

### Phase 4：多资产组合与虚拟电厂聚合

**目标**：把单资产储能扩展为风、光、储能、可控负荷和充电设施组合。

**交付物**：

- 统一资源能力曲线和可用性契约。
- 场站、多节点、变压器/并网点和聚合容量约束。
- 对外聚合报价与对内资源分配的两层决策。
- 从 `user_side_dispatch` 恢复必要的用户侧/分布式内核；通过桥接层转换契约，
  不把固定零售电价字段直接并入市场主契约。
- 内部收益、偏差、退化和违约责任分摊。

**验收标准**：

- 单资源计划汇总后与市场成交和计量守恒。
- 聚合层承诺在所有保留场景下满足可执行性或显式报告违约风险。
- 用户侧模块只有在指定 owner、活动入口和活动测试齐备后解档。

### Phase 5：售电公司、批发用户与需求响应联动

**目标**：覆盖用电侧作为市场主体的采购、定价和响应业务。

**交付物**：

- 零售合同、套餐、电价和用户组合契约。
- 用户级/组合级负荷预测与层级协调。
- 中长期采购、现货采购、零售售电和偏差成本联合优化。
- 需求响应基线、可用容量、参与决策、履约和用户补偿。
- 用户侧账单与批发市场损益分账。

**验收标准**：

- 可追溯每个用户对组合负荷、偏差和利润的贡献。
- DR 收益不与原有电能量收益重复计算。

### Phase 6：市场出清、网络约束与结算风控

**目标**：在参与方算法之外，增加可选的市场研究/仿真能力。

**交付物**：

- 机组组合、安全约束经济调度或简化网络出清模型。
- 节点/分区价格、线路约束、备用需求和阻塞分析。
- 市场运营机构视角与参与方视角严格分包。
- 结算对账、信用敞口、保证金、异常成交和规则版本追踪。

**验收标准**：

- 参与方不能通过代码路径读取出清模型的未来或私有信息。
- 出清结果满足功率平衡、网络和机组物理约束，并可独立审计。

### Phase 7：容量、绿证、碳与金融衍生品

**目标**：支持电能量之外的跨市场组合与长期风险管理。

**交付物**：

- 容量义务和可靠性产品。
- 绿证/碳属性的产生、账户、交易和履约。
- 差价合约、远期或期权等金融头寸。
- 跨市场现金流、风险限额和压力测试。
- 与 `investment_estimation` 的边界接口：投资层提供资产方案，交易层输出可审计的
  运行收益分布，双方不共享实时执行职责。

**验收标准**：

- 能源电量、环境属性和金融现金流分别记账，避免重复计算。
- 每个产品均有规则版本、交易事件、结算和回测证据链。

## 7. 优先级与范围控制

### 7.1 推荐优先级

当前最合理的顺序是：

1. Phase 0 统一领域契约和市场时序。
2. Phase 1 补齐当前蒙西电能量交易闭环。
3. Phase 2 做实中长期—现货组合风险管理。
4. 根据真实业务主体二选一：
   - 独立储能/发电侧优先：进入 Phase 3 辅助服务。
   - 虚拟电厂/售电侧优先：进入 Phase 4—5 聚合与零售。
5. Phase 6—7 只在有明确研究或产品需求时启动。

### 7.2 当前不应做的事情

- 不把所有能源优化模块重新塞回 `optimization/`。
- 不把 `user_side_dispatch` 的固定分时电价契约直接当作批发市场契约。
- 不把 `investment_estimation` 的 IRR 或容量搜索当成实时交易策略。
- 不在缺少真实市场规则时硬编码罚金、回收、价格限幅或产品参数。
- 不用合成样例数据声称获得生产级收益或预测效果。
- 不在没有成交结果的情况下把资源运行计划描述成完整市场报价与出清。

## 8. 各模块在路线中的复用方式

| 当前模块 | 保留职责 | 后续扩展方向 |
|----------|----------|--------------|
| `data_provider` | 数据快照、质量、as-of、版本 | 市场事件、订单、成交、计量和规则版本适配 |
| `forecasting` | 统一预测契约和透明基线 | 生产模型 adapter、概率校准、售电用户组合预测 |
| `scenario` | 联合场景与缩减 | 成交、可用率和多市场相关风险 |
| `optimization` | 通用储能物理、MPC、随机风险内核 | 多资产、多产品、机会成本和组合风险内核 |
| `trading` | 蒙西参与方交易编排、结算、回测 | 报价/成交契约、市场适配器和规则插件 |
| `demand_response` | DR 机会成本和参与评估 | 产品化基线、聚合、履约和补偿分摊 |
| `user_side_dispatch` | 归档用户侧与多节点调度资产 | Phase 4/5 按条件解档，通过桥接层接入 |
| `investment_estimation` | 独立投资与容量测算 | 仅交换资产方案和收益分布，不并入实时主链 |

## 9. 研发治理与测试策略

每个新增场景必须同时交付：

1. 业务规则说明和适用市场版本。
2. typed 输入/输出契约和单位定义。
3. 数据可见时点、版本与质量约束。
4. 可求解的最小实例和失败模式。
5. 结算公式与逐项现金流测试。
6. 无前瞻 walk-forward 回测。
7. 无策略、确定性、风险策略和 oracle 等基准对照。
8. 性能预算、求解状态和降级/回退行为。
9. 活动 app/config 入口；样例数据明确标注为非生产数据。
10. 模块 README 和本路线文档的实现状态同步。

状态升级规则：只有同时具备 owner、真实业务规则、活动入口和常规测试的能力，才可以
从“归档/部分实现”升级为“活动已实现”。算法文件存在本身不等于场景已经实现。

## 10. 结论

当前项目已经形成一条有明确地区和结算口径的纵向链路：面向储能或聚合资源的蒙西
中长期/月度头寸、次日运行、日内滚动、单结算和回测，并具备预测、联合场景、MPC 和
Two-stage + CVaR 基础。它是“市场侧储能交易决策原型”，不是全主体、全品种、全市场
的电力交易平台。

项目还保留两类相关但边界不同的资产：归档的工商业用户侧风光储调度，以及独立的投资
测算包。未来实现全场景能力时，应以统一领域契约和完整电能量交易闭环为起点，再向
中长期组合、辅助服务、虚拟电厂、售电与需求响应、市场出清以及环境和金融产品扩展。
扩展原则不是合并所有模块，而是保持主体、市场规则、外部交易、内部调度和投资规划的
职责边界，通过稳定契约和桥接层复用底层预测、场景、物理和风险算法。
