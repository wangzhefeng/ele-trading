## 1. 调研范围与方法

通过 web 搜索与 GitHub topics 覆盖以下方向：

1. 电力市场交易通用算法库（electricity-market、power-market）；
2. 电力系统仿真与优化框架（agent-based、power system optimization）；
3. 报价策略与强化学习（bidding strategy、reinforcement learning electricity）；
4. 中国电力现货市场相关项目（蒙西、广东、现货报价）。

检索覆盖英文与中文关键词，时间截至 2026-08-02。下文数据（Stars、最新版本、维护方）以该日期为准。

## 2. 电力市场仿真框架（系统级，Agent-based）

这一类解决“市场整体行为仿真”，关注多主体交互和市场设计研究，不是单个交易主体的报价策略。

| 项目 | 语言/协议 | 维护方 | Stars | 最新版本 | 参考价值 |
|---|---|---|---|---|---|
| **ASSUME** [github](https://github.com/assume-framework/assume) | Python / AGPL-3.0 | 弗莱堡大学 INATECH + KIT + Fraunhofer | 102 | v0.5.6 (2025-12) | ★★★ 架构可参考 |
| **AMIRIS** [DLR](https://www.dlr.de/en/ve/research-and-transfer/research-infrastructure/modelling-tools/amiris) | Java / Apache 2.0 | 德国航空航天中心 | — | 持续维护 | ★★ |
| **AMES Test Bed** | Java/Python | Iowa State (Tesfatsion) | — | 学术项目 | ★★ 学术 |
| **Power TAC** | Java | Power Trading Agent Competition | — | 竞赛驱动 | ★ 零售侧 |

### 2.1 ASSUME（重点）

ASSUME 是目前工程化程度最高的开源电力市场 agent-based 仿真框架：

- 定位欧洲/德国市场（EUPHEMIA day-ahead + balancing market），面向研究用途；
- 把 agent（发电侧、需求侧）、市场配置、报价策略做成插件化模块；
- 集成深度强化学习（DRL）作为学习型 bidding strategy，支持 PPO 等；
- 有 SoftwareX 2025 论文、Docker、测试、examples、readthedocs；
- 由德国联邦经济与气候保护部（BMWK）资助。

**与 ele-trading 的关联**：其“learning bidding strategy 作为可插拔 agent”的封装思路，与本项目 `domain←markets←positions/operations` 分层方向一致。但其市场出清层面向欧洲统一出清，与蒙西模式不匹配，**不能直接搬**。

**值得精读**：`bidding` 与 `learning` 子模块的接口设计。

### 2.2 AMIRIS / AMES

- **AMIRIS**（DLR）：agent-based，聚焦德国市场政策评估，工程化程度低于 ASSUME；
- **AMES**（Iowa State）：经典学术项目，定位 ISO 视角的批发市场仿真（day-ahead + real-time + ISO）；
- openmod wiki 上还列出一批同类型研究代码（MASCEM、EMCAS、EMMA、Balmorel、Dispa-SET、NEMO 等），均为研究属性。

## 3. 报价策略 / RL Bidding（单点研究项目）

这一类贴近“单个主体的报价策略”需求，但均为学术 demo 级，无生产可用性。

| 项目 | 内容 | 成熟度 | 参考价值 |
|---|---|---|---|
| **jlp237/MA-VPP-RL-bidding** [github](https://github.com/jlp237/MA-VPP-RL-bidding) | 硕士论文：VPP 跨多欧洲市场（FCR/DA/aFRR/mFRR/Intraday/Imbalance）容量分配+报价，Gymnasium+SB3 | 中（架构完整，仅 FCR 实现，其余 stub） | ★★★★ 架构最像 ele-trading |
| **anthonymakarewicz/algo-electricity-trading** [github](https://github.com/anthonymakarewicz/algo-electricity-trading) | 德国日内 imbalance vs day-ahead 价差方向预测，树模型 | 低 | ★★ 价差预测思路 |
| **Thomas-Haydn/Q-learning-electricity-market** [github](https://github.com/Thomas-Haydn/Q-learning-electricity-market) | 单文件 Q-learning 模拟统一价格拍卖 | 极低（3 commits，教学） | ★ |
| **24447808721/Electricity-market-games-and-price-predictions** [github](https://github.com/24447808721/Electricity-market-games-and-price-predictions) | 中国现货，ABM 建模 549 台机组博弈，出清价预测，15min 频率 | 低（数据竞赛代码） | ★★★ 唯一中国现货数据 |

### 3.1 jlp237/MA-VPP-RL-bidding（重点）

VPP 跨市场容量分配与报价策略的 RL 实现：

- `markets/base.py`：Market 抽象基类（`simulate()` / `calculate_reward()` / `get_capacity_commitment()`）；
- `markets/registry.py`：市场发现与实例化；
- 容量预算追踪器：`allocate → commit → next`，强制跨市场容量约束；
- 支持 8 种 SB3 算法（PPO/A2C/TRPO/RecurrentPPO/SAC/DDPG/TD3/TQC）；
- 配置驱动（TOML），Optuna 超参搜索，WandB 可视化。

**与 ele-trading 的关联**：该项目的 `markets/base.py`（Market ABC）、`markets/registry.py`、跨市场容量预算追踪器设计，与本项目“市场规则按结算模式组织为 `markets/<模式>/` 插件”思路几乎同构。区别在于：该项目面向欧洲多市场序列（FCR→aFRR→mFRR→DA→Intraday→Imbalance），本项目面向蒙西单市场多结算模式。其 `domain/enums + dataclasses` 分层与本项目一致。**可作为架构对照参考**。

### 3.2 Electricity-market-games-and-price-predictions

目前唯一使用**中国电力现货真实数据**的开源项目：

- 15 分钟结算频率，一天 96 个交易点；
- 549 台发电机组；
- 用 ABM（agent-based modeling）模拟机组报价博弈，使模拟出清价逼近真实；
- 数据范围 2021-12 至 2024-04。

代码质量为数据竞赛水平，但**数据口径与中国市场规则理解**具有参考价值。若回测需要“对手方/市场出清响应”模拟器，其 549 机组博弈建模思路可参考。

### 3.3 anthonymakarewicz/algo-electricity-trading

德国市场日内策略：预测 imbalance price 与 day-ahead price 的价差方向，用 ensemble tree 模型。思路对“价差预测/偏差管理”方向有借鉴，但面向德国市场机制。

## 5. 国内相关算法资源

针对中国市场专门调研。结论是：**国内没有公开的、可直接复用的电力市场交易策略开源库**。现货出清与交易算法集中在国电南瑞、清能华曼、许继等企业的闭源技术支持系统中；公开侧只有数据竞赛代码、学术实现和商业 SaaS。

### 5.2 SCUC/SCED 出清求解（系统侧）

中国省级现货市场出清采用 **SCUC（安全约束机组组合）+ SCED（安全约束经济调度）**，计算 LMP 节点电价。这一层是电网/ISO 视角，开源实现以学术教学为主：

| 项目 | 语言 | 内容 | 对 ele-trading |
|---|---|---|---|
| **xuwkk/power_system_operation** [github](https://github.com/xuwkk/power_system_operation) | Python (cvxpy) | NCUC、ED、stochastic UC，含 IEEE 14/39/118 节点算例与数据生成 | ★★ 出清建模教学参考 |
| **ames-market/psst-archive** [github](https://github.com/ames-market/psst-archive) | Python | Python 版 SCUC/SCED 市场仿真（归档） | ★★ |
| **Power-Systems-Optimization-Course** [github](https://github.com/east-winds/power-systems-optimization) | Python/Jupyter | MIT/Conejo 教材配套课程，含 UC/ED/LMP 全链路 notebook | ★★★ 教学最完整 |
| **UnitCommitment.jl** | Julia/JuMP | IEEE Task Force 维护的 SCUC 标准包 | ★（语言不匹配） |
| **PSST** / **HIPPO** | Python | PNNL 的 SCUC 工具（含并行安全校核） | ★★ |

**判断**：若 ele-trading 需要自建出清模拟器（用于回测中的"市场出清响应"），`xuwkk/power_system_operation` 和 Power-Systems-Optimization-Course 可作为 UC/ED/LMP 建模的教学起点。但它们面向 IEEE 标准算例，不含中国省级电网拓扑和真实报价数据，距离蒙西实际出清差距很大。

### 5.3 数据竞赛 baseline

国内电力市场方向的算法竞赛资源稀少，公开 baseline 有限：

- **天池/DataFountain**：搜索未发现活跃的电力现货出清或报价策略竞赛。
- **Inter-IIT optimal-bidding** [github](https://github.com/rahuliitg/optimal-bidding)：印度 Inter-IIT 竞赛，带光伏+储能的社区日前报价优化，含公开/私有数据集。规则是统一出清价，与中国节点电价不同。代码为竞赛 notebook 级。

国内电力现货交易算法的实际载体是**闭源商业系统**，此处仅记录存在性，不代表可参考其实现：

### 5.5 中文学术论文中的算法实现（无公开代码）

检索到多篇中国现货市场报价策略论文，但**均未公开代码**：

- 基于混合博弈强化学习的虚拟电厂市场交易策略（2025）——演化博弈 + RL；

这些论文提供了**算法建模思路**（双层博弈、RL 报价、ABM 出清），但实现需自行复现，无现成代码。

这些文档对 ele-trading 的 `markets/<模式>/` 插件实现是直接的业务需求来源，但不是算法库。

## 6. 结论与建议

### 6.1 整体判断

**全球范围内都没有可直接复用的库。** 电力市场交易强依赖地区规则，蒙西的“日前预出清不结算 + 单偏差结算 + 全电量竞价 + 用户侧不报量不报价 + 分区节点加权平均价”组合在全球独一份，没有任何开源框架覆盖该结算模式。

国内市场更特殊：现货出清与交易算法的核心实现集中在国电南瑞、清能华曼等企业的闭源技术支持系统中，公开侧只有数据竞赛代码（549 机组 ABM）、学术教学代码（IEEE 标准算例 UC/ED）和闭源商业 SaaS（ElecTrade 等）。没有任何开源库覆盖中国省级现货市场的完整规则。

这与 ele-trading 把结算模式插件化（`markets/<模式>/`）的设计判断一致——市场规则必须自写，外部库无法提供现成实现。

### 6.2 对 ele-trading 有参考价值的点

1. **ASSUME 的 learning bidding strategy 插件化封装**（DRL agent 作为可挂载策略）——对报价策略算法层的接口设计有借鉴价值。建议精读其 `bidding` 与 `learning` 子模块。
2. **MA-VPP-RL-bidding 的 market ABC + registry + 容量预算追踪**——架构思路与本项目分层同构，可对照验证本项目设计是否漏了跨市场/跨品种的容量约束这类问题。
3. **Electricity-market-games 的中国现货 ABM 出清模拟**——如果回测需要“对手方/市场出清响应”模拟器，其 549 机组博弈建模思路可参考。
4. **Power-Systems-Optimization-Course（UC/ED/LMP 全链路 notebook）**——若需自建出清模拟器用于回测，这是最完整的教学起点。
5. **ElecTrade 的六类价格预测模型分类**（多智能体/基本面/简化形式/统计学/AI/组合）——可与 ele-trading 的 `forecasting` 模块设计对照。

### 6.3 明确不建议引入的

- **PyPSA**、**AMIRIS**、**AMES**、**Power TAC**——规则错位太大，引入成本高于自写，定位也与本项目正交。
- **vn.py**、**MyEMS**——前者是金融量化框架，后者是能源管理系统，均与电力市场交易策略无关。
- **UnitCommitment.jl**——语言不匹配（Julia），且 ele-trading 使用 Python + PuLP/cvxpy 技术栈。
