## 1. 范围

本文覆盖：

- `src/ele_trading/` 中的活动电力市场交易、预测、场景、优化、运行、结算和回测代码；
- `app/` 下对应活动入口；
- `configs/` 下对应活动配置；
- 相关活动测试以及作为边界说明的归档用户侧模块。

本文不覆盖：

- 平级、自包含的 `src/investment_estimation/`；
- 投资收益测算、容量搜索和资源仿真；
- 真实生产数据、真实市场规则标定或生产部署成熟度。

## 2. 成熟度分类

| 分类 | 定义 |
|---|---|
| 契约稳定 | 当前代码和测试共同约束的跨模块输入、输出或行为边界 |
| 可运行基线 | 可通过样例或测试完成端到端运行，但不代表生产效果 |
| 启发式 | 使用透明规则或简化假设，不是完整市场优化或统计标定模型 |
| 兼容接口 | 为既有调用保留的窄 API，不是当前推荐扩展面 |
| 归档 | 与活动主链隔离，默认不进入常规入口和测试 |
| 生产未验证 | 缺少真实数据、真实规则、外部供应商或生产运行验证 |

## 3. 当前活动链路

```text
数据与配置
  → 价格 / 负荷 / 风电 / 光伏预测
  → 联合场景生成与缩减
  → 中长期与月度头寸
  → 日前运行计划
  → 日内滚动调整
  → 单结算
  → walk-forward 回测与指标
```

当前默认活动链是单结算链。双结算已有独立结算规则实现和测试，但没有接入头寸、日前、日内、编排和回测。

## 4. 模块与实际职责

| 模块 | 当前职责 | 成熟度 |
|---|---|---|
| `domain` | 共享交易契约、决策追踪和事件类型 | 契约稳定；事件类型尚未进入运行链 |
| `data_provider` | 市场快照、资产配置、样例价格、气象 IO 与质量处理 | 契约稳定；外部数据接入生产未验证 |
| `forecasting` | 统一预测请求/结果、registry、价格/负荷/风光/天气模型与指标 | 契约稳定；模型以可运行基线为主 |
| `scenario` | 联合场景、LHS/MC 采样、相关性注入和 Wasserstein L1 缩减 | 可运行基线；误差分布未做生产标定 |
| `optimization` | BESS 套利、MPC、Two-stage + CVaR、共享部分 BESS 物理约束 | 可运行基线；MPC 尚未复用共享物理核 |
| `positions` | 中长期覆盖、月度阶梯报价、缺口再平衡和透明走廊 | 启发式 |
| `operations` | 日前运行、日内滚动、DR 联合优化、求解失败回退 | 可运行基线 |
| `markets` | 单结算与双结算规则实现、配置加载和结算时段聚合 | 单结算可运行；双结算未接主链 |
| `demand_response` | 独立 DR 机会成本和参与判定 | 启发式 |
| `trading` | 固定四类预测、场景、日前、日内和单结算的统一编排 | 可运行基线 |
| `backtest` | 无储能/确定性/风险/oracle 对照、BESS 与退化指标 | 可运行基线；主要基于样例数据 |
| `user_side_dispatch` | 用户侧、分布式和 CVXPY 调度 | 归档 |
| `utils` | YAML、时间、数值、数据对齐和日志工具 | 活动通用工具 |

## 5. 核心契约

当前跨模块主要契约包括：

- 数据：`MarketDataSnapshot`、`ObservedPowerSeries`；
- 预测：`ForecastRequest`、`ForecastResult`、`ForecastProvider`；
- 场景：`Scenario`、`ScenarioSet`；
- 交易：`PositionState`、`MarketForecastBundle`、`OperationalPlan`、`IntradayPlan`、`DRCommitment`、`DecisionTrace`；
- 单结算：`MarketConfig`、`SettlementReport`；
- 求解：`SolveStatus`、`SolverResult`。

其中时间、时区、`issue_time`、`feature_as_of`、版本和观测截止时刻已受到活动测试约束。

## 6. 入口与配置

活动入口：

- `app/optimization/`：BESS 套利、MPC、Two-stage + CVaR，共 3 个；
- `app/trading/`：统一 pipeline、中长期、月度、日前、日内、DR、回测，共 7 个。

当前配置：

- `configs/optimization/bess.yaml`：BESS 套利和 MPC 样例参数；
- `configs/markets/single_settlement.yaml`：单结算链的市场、场景、BESS、DR、月度与求解参数；
- `configs/markets/dual_settlement.yaml`：双结算规则参数；
- `configs/user_side_dispatch/`：归档用户侧入口配置。

当前 `markets.single_settlement.MarketConfig` 同时承载市场、场景、设备、DR、月度和求解参数，是 v3 需要重新评估的组合大对象。

## 7. 实际依赖与架构缺口

1. `positions`、`operations`、`demand_response`、`trading` 和 `backtest` 直接依赖单结算配置或结算实现，因此当前只是结算规则插件化，不是完整交易策略插件化。
2. `optimization.bess_model` 已被部分套利、Two-stage 和日前模型复用，但 MPC 仍维护独立的 SOC、功率和互斥约束。
3. 日前、日内和 Two-stage 文件同时承担模型构建、目标函数、求解、结果提取和追踪，职责较集中。
4. `domain.events` 已提供 `Forecast→Bid→Award→Dispatch→Metering→Settlement` 类型，但活动编排没有消费这些事件。
5. 中长期、月度和独立 DR 决策主要依赖透明规则或简化概率，而非经过真实订单簿和历史误差标定的模型。
6. 预测和场景能力具备工程接口，但真实供应商、生产误差分布和真实市场数据尚未验证。

## 9. 更新触发条件

出现以下任一情况时，必须重新核对并更新本文：

- 模块、公共契约或包依赖方向变化；
- 活动入口或配置结构变化；
- 默认市场模式、结算公式或编排链变化；
- 算法从启发式升级为标定模型或反向变化；
- active-only 测试范围、命令或结果变化；
- 归档模块重新进入活动主链。
