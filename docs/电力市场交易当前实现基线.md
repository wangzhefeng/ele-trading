## 1. 范围

本文覆盖：

- `src/ele_trading/` 中的活动电力市场交易、预测、场景、优化、运行、结算和回测代码；
- `app/` 下对应活动入口；
- `configs/` 下对应活动配置；
- 相关活动测试以及已恢复为独立领域能力的用户侧模块。

本文不覆盖：

- 平级、自包含的 `src/investment_estimation/`；
- 投资收益测算、容量搜索和资源仿真；
- 真实生产数据、真实市场规则标定或生产部署成熟度。

## 2. 成熟度分类

| 分类 | 定义 |
|---|---|
| 契约稳定 | 当前代码和测试共同约束的跨模块输入、输出或行为边界 |
| 可运行基线 | 可通过样例或测试完成端到端运行，但不代表生产效果 |
| 启发式 | 使用透明规则或简化假设，不是完整市场优化或统计标定模型 |
| 归档 | 与活动主链隔离，默认不进入常规入口和测试 |
| 生产未验证 | 缺少真实数据、真实规则、外部供应商或生产运行验证 |

## 3. 当前活动链路

```text
数据与配置
  → 价格 / 负荷 / 风电 / 光伏预测
  → 联合场景生成与缩减
  → 中长期与月度头寸
  → 日前运行计划
  → 日内滚动调整
  → 单结算（经 MarketMode 协议注入）
  → walk-forward 回测与指标
```

当前默认活动链是单结算链，市场模式经 `markets.protocol.MarketMode` 协议在 app 入口（组合根）选择注入；双结算已实现同样的协议装配（`DUAL_SETTLEMENT_MODE`），但尚无头寸/运行/编排的主链用例。用户侧调度为独立领域能力，与市场主链互不依赖。

## 4. 模块与实际职责

| 模块 | 当前职责 | 成熟度 |
|---|---|---|
| `domain` | 共享交易契约、决策追踪、事件类型（含 `MarketCalendar` 与 `derive_input_versions`） | 契约稳定；事件链已进入编排与回测 |
| `data_provider` | 市场快照、资产配置、样例价格、气象 IO 与质量处理 | 契约稳定；外部数据接入生产未验证 |
| `forecasting` | 统一预测请求/结果、registry、价格/负荷/风光/天气模型与指标 | 契约稳定；模型以可运行基线为主 |
| `scenario` | 联合场景、LHS/MC 采样、相关性注入和 Wasserstein L1 缩减 | 可运行基线；误差分布未做生产标定；legacy 价格采样 API 已删除（v3 D-007） |
| `optimization` | 共享 BESS 物理核（bess_model）、目标组件层（objectives）、统一结果提取（extraction）、统一求解出口（solver）、套利/MPC/Two-stage + CVaR | 可运行基线；MPC 已迁移共享物理核（v3 D-004） |
| `positions` | 中长期覆盖、月度阶梯报价、缺口再平衡和透明走廊 | 启发式 |
| `operations` | 日前运行、日内滚动、DR 联合优化、求解失败回退；结算差价经 SettlementEngine 注入 | 可运行基线 |
| `markets` | `protocol`（MarketMode/SettlementEngine）、`sections`（六子对象配置词汇 + schema_version）、单/双结算插件（各含 contracts/loader/settlement/mode 装配） | 单结算可运行；双结算经协议可注入 |
| `demand_response` | 独立 DR 机会成本和参与判定 | 启发式 |
| `trading` | 固定四类预测、场景、日前、日内和结算的统一编排；构建并输出事件链 | 可运行基线 |
| `backtest` | 无储能/确定性/风险/oracle 对照、BESS 与退化指标；事件链完整性断言 | 可运行基线；主要基于样例数据 |
| `user_side_dispatch` | 用户侧、分布式和 CVXPY 调度（独立领域能力，v3 D-001/M6 恢复） | 可运行基线；只依赖 utils |
| `utils` | YAML、时间、数值、数据对齐和日志工具 | 活动通用工具 |

## 5. 核心契约

当前跨模块主要契约包括：

- 数据：`MarketDataSnapshot`、`ObservedPowerSeries`；
- 预测：`ForecastRequest`、`ForecastResult`、`ForecastProvider`；
- 场景：`Scenario`、`ScenarioSet`（唯一 canonical API）；
- 交易：`PositionState`、`MarketForecastBundle`、`OperationalPlan`、`IntradayPlan`、`DRCommitment`、`DecisionTrace`；
- 事件：`TradingEvent` 全链（Forecast/Bid/Award/Dispatch/Metering/Settlement）、`MarketCalendar`、`derive_input_versions`；
- 市场模式：`MarketMode`、`SettlementEngine` 协议；六配置子对象（`MarketSection`/`ScenarioSection`/`BessSection`/`DrSection`/`MonthlySection`/`SolverSection`）+ 组合 `MarketConfig` + `schema_version`；
- 单结算：`SettlementReport`；
- 求解：`SolveStatus`、`SolverResult`。

其中时间、时区、`issue_time`、`feature_as_of`、版本、观测截止时刻、事件链完整性和主链零具体模式依赖已受到活动测试约束。

## 6. 入口与配置

活动入口：

- `app/optimization/`：BESS 套利、MPC、Two-stage + CVaR，共 3 个；
- `app/trading/`：统一 pipeline、中长期、月度、日前、日内、DR、回测，共 7 个；
- `app/user_side_dispatch/`：用户侧 PV/BESS/联合/CVXPY 调度，共 4 个。

当前配置：

- `configs/optimization/bess.yaml`：BESS 套利和 MPC 样例参数；
- `configs/markets/single_settlement.yaml`：单结算链配置（schema v1 六区段：market/scenario/bess/dr/monthly/solver）；
- `configs/markets/dual_settlement.yaml`：双结算规则参数；
- `configs/user_side_dispatch/`：用户侧入口配置，共 4 个。

旧扁平格式单结算 YAML 由 `scripts/migrate_market_config_v3.py` 一次性迁移（已验证等价），loader 对缺失/不匹配的 schema_version 显式报错。

## 7. 实际依赖与架构缺口

1. 中长期、月度和独立 DR 决策主要依赖透明规则或简化概率，而非经过真实订单簿和历史误差标定的模型。
2. 预测和场景能力具备工程接口，但真实供应商、生产误差分布和真实市场数据尚未验证。
3. 双结算已具备协议装配和规则测试，但缺主链用例（报价契约待 v4 设计）。
4. 用户侧需量控制的经济规则（需量结算口径、合同需量规则等六项）待业务侧确认，见 [需量预测算法设计方案-v0.md](需量预测算法设计方案-v0.md) 待确认问题。

v3 已闭环的历史缺口（M0–M6 迁移解决，验收证据见 v3 §11）：五包对单结算的直接依赖、MPC 独立物理核、模型构建职责集中、事件契约空转、扁平 MarketConfig、legacy 场景 API 并存、用户侧归档隔离。

## 8. 验证快照

2026-08-02 在 `dev` 分支（v3 M0–M6 迁移后）执行以下 active-only 验证：

```bash
UV_CACHE_DIR=.uv_cache uv run python -m pytest -q \
  tests/domain tests/optimization tests/forecasting tests/scenario \
  tests/data_provider tests/utils tests/trading tests/positions \
  tests/backtest tests/markets tests/user_side_dispatch \
  tests/test_structure_layers.py tests/test_v2_phase1b_structure.py \
  tests/test_v2_phase2_contracts.py tests/test_yaml_config_loading.py \
  tests/test_entry_scripts.py
```

结果：`470 passed, 4 skipped, 3 deselected`（4 skipped 为手动验收的重型/外部数据入口；3 deselected 为 slow 性能测试）。

该结果证明当前接口、样例和活动链路能够回归，不证明预测精度、策略收益、市场规则参数或生产数据接入有效。

## 9. 更新触发条件

出现以下任一情况时，必须重新核对并更新本文：

- 模块、公共契约或包依赖方向变化；
- 活动入口或配置结构变化；
- 默认市场模式、结算公式或编排链变化；
- 算法从启发式升级为标定模型或反向变化；
- active-only 测试范围、命令或结果变化；
- 市场模式插件新增或事件契约变化。
