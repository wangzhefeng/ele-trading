## 1. v2 目标与成功标准

### 1.1 目标

v2 将 `ele_trading` 从“交易主线、用户侧调度、投资样例、通用实验脚本混合存在”的研究型包，重构为边界清晰、可回测、可接生产数据的电力交易算法包：

1. 活动代码只服务电力交易及其直接依赖的数据、预测、场景、求解、结算和回测。
2. 用户侧储能、用户侧风光储、分布式调度及其样例进入 `todo/`，不再由活动包导出或被活动入口调用。
3. 蒙西交易链统一为：

   `数据快照 → 多维预测 → 联合场景 → 中长期/月度决策 → 日前运行计划 → 日内滚动 → 单结算 → 回测复盘`

4. 预测完整覆盖气象、价格、风电、光伏和多层级负荷，并以统一契约接入交易算法。
5. 场景生成、缩减与风险优化形成真实闭环，不再是彼此独立的演示模块。
6. 删除重复、失效或属于投资/用户侧口径的活动代码，避免两个同名业务概念并存。

### 1.2 成功标准

- `src/ele_trading/data_provider/` 与 `optimization/` 的活动公开 API 中不存在 `user_side_*`、分布式用户侧调度或 CVXPY 用户侧调度。
- 活动 `app/`、配置、文档和自动化测试不再导入任何 `todo/` 模块。
- 交易全链路不使用 `Q_dayah`、`Cpen_dayah` 作为财务结算字段。
- 任一交易决策可追溯到 `as_of` 数据快照、预测 `issue_time`、场景版本、配置版本和求解状态。
- 价格、负荷、气象、风电和光伏预测均能通过同一 Provider 门面按范围、粒度、预测期和分位点调用。
- 两阶段模型真实消费联合场景及缩减后权重；场景采样默认 LHS，保留 `method="mc"`；缩减使用 Wasserstein/Kantorovich L1 后向缩减。
- 所有市场参数均来自 `configs/markets/single_settlement.yaml`，15 分钟模型显式使用 `dt=0.25`。
- 交易主链单元测试、无前瞻回测、入口冒烟测试和 30 日回归基线全部通过。

## 2. 当前实现评估

### 2.1 架构现状

当前 `trading/` 已实现中长期、月度、日前、日内、需求响应、结算和回测的基本骨架，但周边平级模块仍保留大量历史实验：

- `data_provider/` 同时提供交易数据、投资 case、年度负荷构造、用户侧样例和资源仿真数据。
- `optimization/` 同时包含市场优化内核、用户侧调度、分布式调度及一个已部分启用的 `todo/`。
- `control/rolling_dispatch.py` 只是 `optimization.mpc_bess` 的一层转发。
- `demand/` 是最大需量和用户侧需量电费计算，不是交易负荷预测，也不属于蒙西交易主链。
- `evaluation/` 混合了蒙西回测、通用套利指标、IRR、用户侧执行仿真和旧收益结算。
- `forecasting/` 具备若干模型和气象特征函数，但没有形成生产可用的多任务预测服务。
- `scenario/` 与 `two_stage_cvar.py` 各自存在，却没有接入日前或中长期决策。
- `utils/` 混有真正通用工具、用户侧电价工具、绘图应用和重复时间函数。

### 2.2 预测场景覆盖结论

| 预测场景 | 当前实现程度 | 主要问题 | v2 目标 |
| --- | --- | --- | --- |
| 气象预测 | 未覆盖 | 只有 Open-Meteo 获取、NetCDF/Mongo 读取、模拟和特征工程，没有气象预测契约与模型 | 支持外部 NWP 接入、历史回放和可选订正模型 |
| 日前/实时价格 | 部分覆盖 | 简单统计/ARIMA 基线存在，但未接入交易入口，市场语义弱 | 点预测、分位预测、日前与实时价联合输出 |
| 中长期价格 | 占位 | `"monthly"` 被简化为 12 个点，没有月份索引与价格带标定 | 月/季度价格分布和价格走廊 |
| 风电出力 | 部分覆盖且物理路径失效 | 统计与物理模型混合，物理路径仍引用已删除的容量规划模块 | 统一统计、物理和外部服务适配器 |
| 光伏出力 | 部分覆盖且物理路径失效 | 与风电相同，缺少统一容量归一化和可用率语义 | 输出功率、容量因子、可用率及分位区间 |
| 负荷预测 | 仅基础占位 | AR 系数训练后未进入递推预测；主要使用气候均值；没有层级维度与协调 | 系统/区域/节点/组合/场站多层级、日前/日内/中长期预测 |
| 联合不确定性 | 未覆盖 | 预测分位区间没有转为价荷风光联合场景 | 构造保相关性的联合场景并接入风险优化 |

### 2.3 算法实现程度

| 模块 | 当前可用部分 | v2 判定 |
| --- | --- | --- |
| 中长期与月度 | 能生成仓位比例、月度分解、阶梯和缺口走廊 | 保留业务意图，替换固定启发式为约束优化和可校准策略 |
| 日前耦合 | 储能计划、SOC、退化和风控约束较完整 | 删除日前申报和双结算目标，重构为单结算下的运行计划 |
| 日内滚动 | 有滚动求解骨架 | 保留并接入真实 forecast vintages、执行状态和回退机制 |
| 需求响应 | 有参与收益比较 | 保留，但去除硬编码补偿参数并补资源可用性契约 |
| 结算 | 双结算 `C/C2/Cpen_dayah` 已实现 | 结算引擎已激活为 `markets/dual_settlement/` 插件；活动主链实现为单结算与中长期差价合约 |
| 回测 | 能执行 30 日样例回放 | 保留框架，消除加噪真值替代生产预测、固定 `DT` 和未来信息风险 |
| 场景与 CVaR | 有 LHS、缩减和两阶段模型骨架 | 整合为统一联合场景与可求解的风险决策链 |

### 2.4 v0 产品接口处置

v0 的接口清单不能在单结算口径下原样继承，v2 按以下方式收敛：

- 保留并升级：合约组合、年度/季度/月度/月内交易、持仓再平衡、双边/集中竞价/滚动撮合/挂牌建议、储能日前计划、日内滚动、实时调整、需求响应、偏差控制和机会损失评估。
- 重新定义：“日前现货量价申报策略”改为“日前运行计划与风险提示”，不再输出财务申报量和申报价。
- 条件启用：对手匹配和中长期成交模拟只有在具备真实订单簿、成交规则和标定样本时启用；否则只输出量价走廊与数据不足原因。
- 延后实现：多场站协同调度，等待共享容量、网络约束、控制权和结算主体明确。
- 不进入活动主线：用户侧需量控制、目录电价套利、投资收益测算和容量 sizing。

## 3. v2 目标架构

### 3.1 分层原则

`trading` 是业务主线和唯一编排入口，但不复制通用能力：

- `data_provider`：只负责交易所需数据快照、外部适配和质量控制。
- `forecasting`：只负责预测契约、模型、层级协调和预测版本。
- `scenario`：只负责预测不确定性到联合场景的转换与缩减。
- `optimization`：只保留无市场规则含义的可复用数学内核。
- `trading`：拥有蒙西规则、业务契约、策略、结算、回测和端到端编排。
- `utils`：只保留无业务语义的小型通用函数。

依赖方向固定为：

```text
data_provider
      ↓
forecasting → scenario
      ↓          ↓
optimization ← trading
                  ↓
        settlement / backtest
```

禁止 `data_provider`、`forecasting`、`scenario`、`optimization` 反向导入 `trading`。跨层数据类型放在所属能力包内，交易层通过组合类型消费，消除当前 `forecasting.provider → trading.contracts` 的反向依赖。

### 3.2 建议目录

- `settlement.py`：旧单市场套利收益计算不属于蒙西结算，删除；需要的基础收益项由交易指标模块明确命名实现。
- `simulation.py`：当前为用户侧电费回放，删除活动版本。交易执行回放需要时按 `OperationalPlan → ExecutedPlan` 契约重写，不复用其含混的正负功率命名。

### 4.7 `scenario`

## 5. v2 核心数据契约

### 5.1 时间与版本

所有数据、预测、场景和决策对象必须携带：

- `market`：固定为受支持的市场代码，例如 `mengxi`；
- `scope_id` 与 `scope_type`；
- `as_of`：数据快照截止时刻；
- `issue_time`：预测或决策出具时刻；
- `valid_time`：目标时间索引；
- `freq_minutes`：现货主链固定 15，月度数据使用明确 PeriodIndex；
- `version`：数据、模型、配置或策略版本；
- `quality_flags`：缺失、插值、降级和外部源异常。

任何 `valid_time` 之前产生、但 `issue_time` 晚于决策时刻的数据均不得进入决策。

### 5.2 预测契约

```python
ForecastRequest(
    target,          # weather | price | load | wind_power | pv_power
    scope_type,      # system | region | node | portfolio | site
    scope_id,
    horizon,
    frequency,
    issue_time,
    quantiles,
)

ForecastResult(
    request,
    point,
    quantiles,
    unit,
    model_version,
    feature_as_of,
    quality_flags,
)
```

目标维度：

- 气象：站点/网格/区域；
- 价格：日前预出清参考、实时参考、中长期；
- 风光：场站、组合、区域；
- 负荷：系统、区域、节点、组合、场站。

层级负荷与新能源预测必须满足聚合一致性；采用 bottom-up 基线与 MinT/约束最小二乘协调，原始预测和协调后预测同时保留。

### 5.3 交易与运行契约

- `PositionState`：当前中长期合约、已成交月度头寸、预算和风险敞口。
- `MarketForecastBundle`：同一 issue time 下价、荷、风、光预测集合。
- `ScenarioSet`：联合轨迹和概率。
- `OperationalPlan`：日前运行计划，只含储能/可调资源计划、SOC、预期成本和风险，不含财务日前申报量。
- `IntradayPlan`：已执行段、剩余计划、调整原因和回退状态。
- `SettlementReport`：实时电量成本、中长期差价合约、中长期回收、DR 收益、退化成本、总成本和基准差异。
- `DecisionTrace`：输入版本、配置哈希、求解器、状态、目标分解和约束激活。

v1 的 `DayAheadPlan.q_dayah`、`bid_prices`、`cpen_dayah` 和财务 `p_dayah` 字段从活动契约删除。

## 6. 蒙西单结算算法

### 6.1 结算口径

日前预出清只作为运行和价格信号，不进入财务结算。基础电能成本：

```text
C_energy[t] = Q_real[t] × p_real[t]
```

中长期合约按差价合约结算：

```text
C_contract[t] = Q_long[t] × (p_long[t] - p_ref[t])
C_total[t]    = C_energy[t] + C_contract[t]
```

若 `p_ref = p_real`，等价于：

```text
C_total[t] = Q_long[t] × p_long[t]
           + (Q_real[t] - Q_long[t]) × p_real[t]
```

中长期缺额/超额回收按确认后的月度签约比例、参考价和配置参数计算。未获得正式规则前，字段保留 `TODO(rule-confirm)`，但不得回退到日前偏差考核替代。

### 6.2 中长期与月度决策

输入：

- 多层级中长期负荷预测；
- 中长期和实时参考价分布；
- 合同候选、交易窗口、预算与持仓；
- 联合场景和风险限额。

目标：

```text
min  ExpectedProcurementCost
   + λ_cvar × CVaRα(Cost)
   + λ_gap × UncoveredEnergy
   + λ_turnover × PositionChange
```

约束覆盖预算、交易最小单位、持仓上下限、分月交付、集中交易规则和最大风险敞口。现有固定 `alpha_long/alpha_dayah/alpha_real` 改为结果指标；单结算下不再把日前作为财务仓位。

### 6.3 日前运行计划

日前模块的职责由“储能 + 日前申报”改为“面向次日实时成本和履约风险的资源计划”：

```text
min  E[实时购电成本 + 中长期差价影响 + 退化成本 + DR履约成本]
   + λ_cvar × CVaRα
   + λ_terminal × 终端SOC偏差
```

保留 SOC、效率、功率、不可倒送、吞吐量、终端 SOC 和可选充放互斥约束。`p_dayah_pre` 只能作为解释性或运行参考特征，不能进入结算公式。

### 6.4 日内滚动

每次滚动：

1. 冻结已执行时段；
2. 读取当前 SOC、资源可用率和最新 forecast vintage；
3. 重建剩余窗口联合场景；
4. 求解剩余计划；
5. 输出计划变化、成本变化、触发原因和约束状态；
6. 求解失败时回退到上次可行计划，经物理边界裁剪后执行。

滚动模型不得读取当前决策时刻之后才发布的实际价格或负荷。

### 6.5 需求响应

DR 继续作为交易产品保留。参与条件比较：

```text
响应补偿
- 放弃的套利/避险收益
- 履约风险成本
- 退化成本
> 最低参与裕度
```

补偿价、违约成本、聚合方式、最小响应量和时间窗口全部进入市场配置，不保留代码内固定补偿值。

## 7. 预测与场景实现方案

### 7.1 气象预测

按优先级提供三类 Provider：

1. 外部 NWP/API 适配器：生产默认；
2. 已发布预报的历史归档：无前瞻回测必需；
3. 统计订正：对温度、辐照度、风速、云量等做偏差订正和分位估计。

天气模拟器只用于测试，不得标记为生产预测。气象预测按站点/网格输出，再由空间权重聚合到场站或区域。

### 7.2 价格预测

- 日前参考：96 点或市场实际发布粒度；
- 实时参考：日前全日预测 + 日内滚动预测；
- 中长期：月/季度分布、价格带和场景。

基线模型包括季节性朴素、ARIMA/回归；生产接口允许外部模型注册。评估指标至少包括 MAE、RMSE、分位损失、区间覆盖率和方向准确率。

### 7.3 风电与光伏出力预测

两者统一支持：

- 物理模型：NWP → 功率；
- 统计订正：历史实测与天气特征；
- 外部服务；
- 场站到组合/区域聚合；
- 可用容量、限电和设备可用率。

输出统一为 MW 功率；交易电量由调用方按 `dt=0.25` 转换为 MWh，避免功率和电量在预测模块内混用。

### 7.4 多维负荷预测

范围维度：

- 系统；
- 区域；
- 节点；
- 聚合组合；
- 场站/用户组。

时间维度：

- 中长期月/季度；
- 日前 96 点；
- 日内剩余窗口；
- 超短期滚动。

模型至少包含季节性朴素基线、AR/回归基线和可插拔外部模型。特征包括历史负荷、日历、气象、价格和事件；预测后执行层级协调。没有足够历史时输出明确降级标识，而不是静默用整体均值。

### 7.5 联合场景

先从各预测任务得到边际分布，再通过历史残差相关、Copula 或块自助法构造价荷风光联合轨迹。v2 首版使用可解释的残差相关 + LHS，后续可替换相关结构而不改变 `ScenarioSet`。

场景缩减后必须验证：

- 权重和为 1；
- 边际均值/分位数偏移在阈值内；
- 关键价差、净负荷峰值和爬坡事件仍被覆盖；
- 相同 seed、输入版本和配置可复现。

## 8. 配置、入口与输出

### 8.1 配置

`configs/markets/single_settlement.yaml` 按以下区段重组：

- `market`：市场、时区、交易日、粒度和单结算模式；
- `settlement`：实时参考点、中长期差价和回收规则；
- `forecast`：Provider、模型版本、分位点和降级策略；
- `scenario`：数量、LHS/MC、相关模型、缩减数和 seed；
- `risk`：CVaR 置信度、权重、敞口和预算；
- `bess`：功率、容量、效率、SOC、退化和 `dt: 0.25`；
- `dr`：产品参数和补偿；
- `solver`：建模框架、求解器、时限和最优性 gap。

删除 v1 中只服务双结算的 `lam_l/lam_u`、`dayahead_mode`、`price_reporting`、`w_pen` 等字段；中长期回收字段在正式规则确认后命名，禁止复用日前偏差字段。

### 8.2 入口

活动入口只保留：

- `run_mid_long.py`
- `run_monthly.py`
- `run_day_ahead.py`
- `run_intraday.py`
- `run_dr.py`
- `run_backtest.py`

新增统一 `run_pipeline.py`，按配置和 `as_of` 执行端到端链路。所有入口通过 `data_provider` 读取生产数据，不硬编码 `data/` 路径。

### 8.3 输出

```text
results/trading/
├── forecasts/<run_id>/
├── scenarios/<run_id>/
├── decisions/<run_id>/
├── settlement/<run_id>/
└── backtest/<run_id>/
```

每个运行目录写入机器可读结果、`manifest.json` 和配置快照。日志记录运行 ID，不在算法内核直接决定文件路径。

## 10. 测试与验收矩阵

### 10.1 结构测试

- 活动源码、app、config、tests 中不存在 `user_side_` 导入，归档引用仅指向 `ele_trading.user_side_dispatch`。
- `control`、`demand`、活动 `evaluation` 不再作为可导入包。
- `forecasting/scenario/optimization/data_provider` 不导入 `trading`。
- `investment_estimation` 继续保持自包含，v2 不修改其内部实现。

### 10.2 契约与数据测试

- 时区、15 分钟索引、月度 PeriodIndex、功率/电量单位严格校验。
- `issue_time <= decision_time`，并验证所有特征的 `as_of`。
- 缺失、重复、乱序、插值和降级均产生质量标记。
- 序列化往返不丢失版本、概率和索引。

### 10.3 预测测试

- 五类预测均覆盖 fit/predict、外部 Provider、失败降级和分位区间。
- 负荷层级协调后父层等于子层汇总。
- 风光输出不超过可用容量，夜间光伏为 0，风机切入/切出边界正确。
- 历史回测只读取当时已发布的气象和价格预测。

### 10.4 场景与优化测试

- LHS 默认、MC 兼容、固定 seed 可复现。
- Wasserstein L1 缩减概率守恒且不是简单 Top-K。
- SOC、效率、功率、终端 SOC、吞吐量和不可倒送约束正确。
- CVaR 辅助变量和手工小样本结果一致。
- 求解失败返回结构化失败，不返回伪可行零解。

### 10.5 交易与结算测试

- 单结算恒等式：

  `Q_real*p_real + Q_long*(p_long-p_real)`

  与

  `Q_long*p_long + (Q_real-Q_long)*p_real`

  在同一参考价下数值一致。
- `p_dayah` 和任何日前计划变化都不直接改变财务结算。
- 中长期回收按月聚合，参数来自配置。
- DR、退化和执行偏差分别列示，不重复计费。
- 中长期、月度、日前、日内和回测可通过统一 orchestrator 串联。

### 10.6 回归与性能

- 96 点确定性 LP：普通开发机目标 ≤ 5 秒。
- 单次日内滚动：目标 ≤ 10 秒。
- 30 日 walk-forward 回测：目标 ≤ 10 分钟。
- 比较基准包括无储能、确定性策略、风险策略和 oracle，仅 oracle 允许使用真实未来价格。

## 11. 风险与待确认项

1. 中长期缺额/超额回收的正式参数、参考价、月度签约比例和计算边界必须依据书面市场规则确认，当前配置继续标记 `TODO(rule-confirm)`。
2. 日前预出清价是否可稳定获得，只影响预测特征和解释，不得改变单结算主线。
3. 多场站协同需要明确共享约束、控制权和结算主体；v2 契约预留 `portfolio/site` 层级，但首版不实现网络潮流。
4. 对手盘数据不可得时，双边、挂牌和撮合只输出量价走廊，不伪造成交概率。
5. 气象外部服务必须归档 issue-time 版本；只有观测真值而无历史预报时，不得宣称完成无前瞻预测回测。

## 12. v1 → v2 关键变化

| v1.3 | v2 |
| --- | --- |
| 日前 + 实时双结算 | 实时电量 + 中长期差价合约单结算 |
| `Q_dayah` 是申报和结算量 | 日前只生成运行计划 |
| `Cpen_dayah` | 从活动主线删除 |
| 预测接口只覆盖价荷 | 统一覆盖气象、价、荷、风、光 |
| `"monthly" → 12` 的弱语义 | 明确 PeriodIndex、目标范围和单位 |
| 场景、CVaR、交易彼此独立 | 联合场景直接驱动风险决策 |
| 用户侧与交易代码混合导出 | 用户侧完整隔离到 `todo/` |
| 回测加噪真值作为主要预测 | forecast vintage 驱动的 walk-forward |
| `evaluation` 有多个结算/回放口径 | 交易结算与回测统一归 `trading` |
| 大型 utils/feature 文件混杂 | 小型通用工具与明确能力模块 |

本文件是 v2 实施的设计基线。实施中若市场规则发生变化，先更新本文件和配置契约，再修改算法，禁止以局部代码行为反向定义业务口径。
