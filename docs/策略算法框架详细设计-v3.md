## 2. 问题定义

v3 的主要目标是优化当前已实现算法的架构、公共契约和实现细节，使物理约束、市场策略、求解、编排和回测之间的边界更清晰。v3 不以继续增加算法数量为主要目标，也不把旧版本的目录、Phase 或实现选择自动视为新版本约束。

## 3. 范围与非目标

### 3.1 范围

- `src/ele_trading/` 中的活动市场交易、预测、场景、优化、运行、结算和回测；
- `app/` 活动入口及其配置装配；
- 现有公共契约、兼容接口、测试和回归基线的迁移策略。

### 3.2 非目标

- 本阶段不设计或修改 `src/investment_estimation/`；
- 默认不恢复 `user_side_dispatch` 归档模块；
- 不以样例数据结果推断生产策略收益；
- 骨架阶段不虚构尚未决策的接口字段和市场规则。

## 4. 当前实现基线

当前事实、成熟度和已验证缺口统一见 [电力市场交易当前实现基线.md](电力市场交易当前实现基线.md)。本文不复制当前实现清单，避免事实描述与目标设计混为一体。

## 5. v3 强制业务不变量

以下约束对 v3 设计和实施均有效：

1. **无前瞻**：决策只能消费决策时刻可获得的数据；预测、特征和场景必须记录实际来源时刻与版本。
2. **时间与单位明确**：时间戳必须明确时区；功率、电量、价格、频率和 `dt` 必须在契约边界声明并一致换算。
3. **市场参数注入**：市场规则、价格限制、考核系数和风险参数不得隐藏在通用算法实现中。
4. **结算唯一计费**：电能、合同差价、回收、DR、退化和执行调整必须有唯一计费归属，不得重复计入。
5. **数据边界**：样例、fixture 和模拟数据只能用于接口、demo 和回归，不能直接作为生产策略评估数据。
6. **失败透明**：求解失败必须返回显式状态或进入有记录、可解释的受控回退，不得伪造成功计划。

## 6. 待重新决策的现有实现

| 议题 | 当前实现 | v3 需要形成的决定 |
|---|---|---|
| 活动市场模式 | 主链固定单结算 | 是否继续单模式，或定义可替换策略接口 |
| 市场插件范围 | 主要覆盖配置与结算 | 是否扩展到头寸、运行、编排和回测 |
| 配置模型 | 单结算 `MarketConfig` 跨多个领域 | 是否拆成组合式 typed config 并引入 schema version |
| BESS 物理核 | 部分模型共享，MPC 独立 | 统一范围、状态契约和迁移顺序 |
| 模型构建边界 | 日前、日内、Two-stage 各自较厚 | 公共物理、目标策略、求解和提取如何拆分 |
| 场景兼容 | LHS/MC、联合场景和 legacy price API 并存 | canonical API、兼容期限和标定边界 |
| 事件契约 | 已定义但未被活动链使用 | 落地、保留为数据类型或删除 |
| 用户侧归档 | 与活动主链隔离 | 长期保留、恢复或删除 |

## 7. 目标架构

本章在相关决策批准后补充完整组件关系、依赖方向和数据流。

### 7.1 领域契约

待明确稳定领域对象、状态转换、事件用途以及版本兼容边界。

### 7.2 数据与预测

待明确生产数据 adapter、预测 registry、历史 vintage、需量预测归属和质量降级策略。

### 7.3 场景与风险

待明确边际分布、相关性、场景缩减、诊断信息及与风险优化的接口。

### 7.4 通用物理与求解内核

待明确 BESS 状态转移、约束构建、求解器 adapter、失败状态和结果提取的唯一实现边界。

### 7.5 市场策略

待明确市场规则、头寸策略、报价策略、DR 产品和结算策略之间的依赖关系。

### 7.6 日前与日内运行

待明确日前计划、滚动重优化、冻结前缀、履约约束和受控回退的共用能力。

### 7.7 编排与结算

待明确编排器的依赖注入接口、市场模式选择、结算策略和决策追踪。

### 7.8 回测与评估

待明确 walk-forward 时间契约、基准组、业务反例、性能预算和生产评估数据要求。

## 9. “需量预测”归属决策

| 业务含义 | 候选归属 | 与现有实现的关系 |
|---|---|---|
| 市场/组合负荷预测 | `forecasting` | 扩展现有 load target 和模型 registry |
| 最大需量控制或需量电费 | 独立领域能力 | 不应与普通负荷预测混为一个模型 |
| 用户侧需量策略 | 与 `user_side_dispatch` 联动 | 必须先决定归档模块是否恢复 |

最终归属必须在需求、输入输出、时间尺度和经济目标明确后写入决策记录。

## 10. 迁移与兼容策略

### 10.1 迁移阶段

待按“契约与回归基线 → 共享物理核 → 配置拆分 → 策略接口 → 编排与回测”的顺序细化，每一阶段必须给出输入、输出、兼容面和退出条件。

### 10.2 兼容策略

待列出 canonical API、legacy API、弃用告警、迁移期限以及删除条件。历史版本号不能代替兼容性说明。

### 10.3 测试策略

待将测试区分为业务不变量、数学正确性、架构边界、兼容回归、入口冒烟和生产数据验收。

### 10.4 性能预算

待为场景生成、日前求解、日内滚动和 30 天 walk-forward 回测分别定义数据规模、硬件环境和时限。

### 10.5 验收标准

待为每项架构决策定义可运行入口、回归基线、业务反例和文档同步要求。
