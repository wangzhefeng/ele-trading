## 2. 背景与当前算法盘点

### 2.1 目标

v3 已评审通过（2026-08-02），确立了目标架构与迁移路径：市场完整策略插件化（`MarketMode` Protocol，D-002）、配置拆分六子对象（D-003）、BESS 物理核统一（D-004）、模型构建边界四层拆分（D-005）、事件契约落地（D-006）、场景 API 收敛（D-007）和用户侧需量领域恢复（D-001），按 M0–M6 阶段迁移。v4 的目标是**增强算法功能本身**，使各模块从"可运行基线/启发式"向"可标定、可验证、可扩展的生产级算法"演进。v4 不改变 v3 的架构边界、依赖方向和迁移阶段划分，只增强各层内部算法实现；凡与 v3 迁移重叠的工作（如 MPC 约束核统一）归 v3 阶段执行，v4 在其完成面上叠加增强。

### 2.2 当前算法实现盘点（基于实际代码）

| 模块 | 当前算法 | 成熟度 | 核心缺口 |
|---|---|---|---|
| `forecasting/price` | seasonal-naive、线性回归、ARIMA 兼容 | 工程基线 | 无概率预测、无 NWP 特征驱动、无市场结构特征、中长期语义弱 |
| `forecasting/load` | 递归 AR、climatology、短历史降级、层级协调 | 工程基线 | 无外部日历/事件特征、无分位输出、层级协调未标定 |
| `forecasting/weather` | vintage 选择、persistence、climatology、bias correction | 工程基线 | 无真实 NWP 接入、无空间插值标定 |
| `forecasting/renewable` | 风/光物理曲线 + 统计订正 + 外部 adapter | 工程基线 | 物理模型无真实设备参数标定、统计订正无误差分布 |
| `scenario/` | LHS/MC 采样、残差相关、Wasserstein L1 缩减 | 可运行基线 | 相关结构为简化残差相关、无 Copula、无极端场景注入 |
| `optimization/bess_model` | SOC 动态、效率、功率、互斥、终端 SOC、吞吐量、no-export | 契约稳定 | 线性退化、无日历退化、无温度耦合 |
| `optimization/bess_arbitrage` | 确定性 LP 套利（CBC） | 可运行基线 | 完美预见 oracle，仅作基准 |
| `optimization/mpc_bess` | 滚动有限时域 MPC（独立约束核，未复用 bess_model） | 可运行基线 | 约束重复实现、无场景、无状态反馈 |
| `optimization/two_stage_cvar` | 两阶段随机规划 + Rockafellar-Uryasev CVaR 线性化 | 可运行基线 | 偏差考核为外部参数、无多资源、无多时段耦合 |
| `optimization/risk` | CVaR 辅助变量 + 离散加权 VaR/CVaR 评估 | 契约稳定 | 仅 CVaR，无 EVaR/最坏场景/机会约束 |
| `positions/mid_long` | 价差 → 覆盖比例启发式映射 | 启发式 | 固定线性映射、无优化、无风险约束 |
| `positions/monthly` | 阶梯报价 + uniform/linear 出清概率 + 透明走廊 | 启发式 | 出清概率为简化模型、无订单簿、无博弈 |
| `operations/day_ahead` | BESS + 联合场景 CVaR + DR 两遍求解 | 可运行基线 | 单资产 BESS、目标函数耦合市场规则、无多资源 |
| `operations/intraday` | 冻结前缀 + 剩余窗口重优化 + 物理裁剪回退 | 可运行基线 | 无状态反馈、无执行偏差学习 |
| `demand_response` | 机会成本估算 + 二值参与判定 | 启发式 | 无聚合、无多产品冲突、无基线市场化 |
| `markets/single_settlement` | 实时电能 + 合同差价 + 月度回收 + 分项报告 | 可运行基线 | 回收参数 `TODO(rule-confirm)`、无账单对账 |
| `backtest/` | 无储能/确定性/风险/oracle 四组 walk-forward | 可运行基线 | 无数据切分契约、无业务反例、样例数据驱动 |

### 2.3 调研结论对算法增强的指引

基于[开源调研](电力市场交易开源算法库调研.md)的结论，算法增强遵循以下判断：

1. **不引入外部框架**：ASSUME、MA-VPP-RL-bidding、PyPSA 等规则错位，引入成本高于自写。
2. **借鉴接口设计**：ASSUME 的"learning bidding strategy 作为可插拔 agent"、MA-VPP-RL-bidding 的"Market ABC + registry + 容量预算追踪"可对照本项目分层验证。
3. **预测模型分类**：参考 ElecTrade 的六类价格预测模型分类（多智能体/基本面/简化形式/统计学/AI/组合），v4 的 forecasting 增强按此分类组织可插拔模型。
4. **出清模拟自建**：参考 Electricity-market-games（549 机组 ABM）和 Power-Systems-Optimization-Course（UC/ED/LMP），在回测层自建轻量市场出清响应模拟器。
5. **中国市场规则自写**：全球无覆盖蒙西"单偏差结算"模式的开源库，市场规则算法必须自实现。

## 3. v4 算法增强目标与设计原则

### 3.1 增强目标

| 维度 | 当前状态 | v4 目标 |
|---|---|---|
| 预测精度 | 工程基线（seasonal-naive/AR） | 引入 ML 基线（LightGBM）、概率预测（分位/分位回归）、外部特征接入 |
| 场景真实性 | 残差相关 + LHS | Copula 相关结构、极端场景注入、场景诊断 |
| 风险度量 | CVaR 单一 | CVaR + 最坏场景 + 机会约束可选 |
| 优化广度 | 单资产 BESS | 多资源联合（BESS + 可调负荷 + 新能源）、退化模型升级 |
| 头寸策略 | 启发式映射 | 约束优化、风险限额、可校准覆盖策略 |
| 报价能力 | 无（日前只出运行计划） | 可选报量报价策略接口（蒙西发电侧报量报价场景） |
| 回测深度 | 样例 walk-forward | 真实数据切分、市场出清响应模拟、业务反例 |
| 执行闭环 | 无状态反馈 | 日内滚动接入执行偏差学习 |

### 3.2 设计原则

1. **算法可插拔，契约不变**：所有算法增强通过 registry/strategy 模式接入，不改变现有 `ForecastRequest`/`ForecastResult`/`ScenarioSet`/`OperationalPlan`/`SettlementReport` 契约。新算法是实现替换，不是契约重定义。
2. **先标定后生产**：任何从"基线"升级到"生产"的算法，必须经过真实数据标定和 walk-forward 回测验证，禁止直接切换默认模型。
3. **风险参数显式注入**：市场规则、风险限额、退化系数不得隐藏在算法内部，必须通过 v3 配置子对象（market/scenario/bess/dr/monthly/solver，D-003）或独立 `RiskConfig`/`StrategyConfig` 显式传入。
4. **无前瞻强制**：所有增强算法在回测中只能消费决策时刻可获得的 forecast vintage，新引入的特征（NWP、日历、事件）必须保留 issue-time 版本。
5. **退化模型渐进升级**：线性退化（当前）→ 日历+循环退化分离 → 温度耦合，按需升级，不一步到位。
6. **报价策略可选**：当前蒙西活动主链不含财务报价；报量报价策略作为**可选能力**实现，由配置启用，不强制进入单结算主链。

## 4. 预测算法增强

### 4.1 增强方向总览

预测层是 v4 增强的重点。当前实现以统计基线为主，v4 引入 ML 基线和概率预测，同时保持统一契约和 registry 机制。

| 预测任务 | 当前模型 | v4 增强模型 | 优先级 |
|---|---|---|---|
| 价格（日前/实时） | seasonal-naive、回归、ARIMA | + LightGBM 点预测、分位回归（pinball loss）、市场结构特征 | P0 |
| 价格（中长期） | 占位 | 月度分布预测、价格走廊（分位带） | P1 |
| 负荷（多层级） | 递归 AR、climatology | + LightGBM、层级协调（MinT/约束最小二乘）、分位输出 | P0 |
| 风电出力 | 物理曲线 + 统计订正 | + NWP 驱动 LightGBM、功率曲线参数标定 | P1 |
| 光伏出力 | 物理曲线 + 统计订正 | + NWP 驱动 LightGBM、夜间/云量边界校验 | P1 |
| 气象 | persistence、climatology、bias correction | + 外部 NWP adapter（Open-Meteo Forecast API / 本地 WRF 输出） | P1 |

### 4.2 概率预测框架

当前 `ForecastResult` 已支持 `quantiles` 字段但模型未输出。v4 为所有预测任务建立统一概率预测能力。

#### 4.2.1 分位预测实现

```text
点预测 μ̂(t)：
  - 统计基线：seasonal-naive / ARIMA / 递归 AR
  - ML 基线：LightGBM（特征：日历、历史滞后、气象、价格滞后）
  - 外部模型：通过 registry 注册的任意 Provider

分位预测 q_τ(t), τ ∈ {0.1, 0.25, 0.5, 0.75, 0.9}：
  方法 A（残差分位）：q_τ(t) = μ̂(t) + F̂_ε⁻¹(τ)
    - F̂_ε 为历史残差经验分布，按时段/季节分桶
  方法 B（直接分位回归）：LightGBM quantile regression，pinball loss 训练
    - L_pinball(τ) = max(τ·ε, (τ-1)·ε), ε = y - q_τ
  方法 C（保形预测 Conformal）：在方法 A/B 基础上用校准集构造非一致性得分
    - s_i = |y_i - μ̂_i| / σ̂_i，取分位数作为区间半宽
    - 保证边际覆盖率 P(y ∈ [μ̂ ± w_τ]) ≥ τ
```

**优先策略**：方法 B（LightGBM 分位回归）作为 ML 基线的主力，方法 C（保形预测）用于需要覆盖率保证的场景。方法 A 作为轻量兼容路径。

#### 4.2.2 概率预测评估

新增评估指标（扩展 `forecasting/metrics.py`）：

| 指标 | 定义 | 用途 |
|---|---|---|
| Pinball Loss | $\frac{1}{T}\sum_t \max(\tau \cdot e_t, (\tau-1) \cdot e_t)$ | 分位预测核心指标 |
| Interval Coverage | $P(y \in [q_{lo}, q_{hi}])$ | 区间可靠性 |
| CRPS | Continuous Ranked Probability Score | 概率预测综合精度 |
| Calibration Plot | 实际覆盖率 vs 标称覆盖率 | 分位偏差诊断 |

### 4.3 价格预测增强

#### 4.3.1 特征工程

```text
价格预测特征矩阵 X(t)：
├── 日历特征：hour、day_of_week、month、is_holiday、is_weekend
├── 滞后特征：price(t-1d)、price(t-2d)、price(t-7d)（同周同时段）
├── 滚动统计：price 滚动均值/标准差（24h、168h 窗口）
├── 负荷特征：load_forecast(t)（来自负荷预测，注意避免循环依赖）
├── 新能源特征：wind_forecast(t)、pv_forecast(t)、净负荷 = load - wind - pv
├── 气象特征：temperature(t)、wind_speed(t)、irradiance(t)
└── 市场结构特征：供需比（forecast_supply / forecast_demand）、历史价格分位
```

**关键约束**：所有特征在决策时刻 $t_{dec}$ 必须可获得，即 `feature_as_of ≤ issue_time ≤ t_{dec}`。负荷和新能源预测作为价格预测特征时，必须使用同一 vintage，禁止价格预测使用未来负荷真值。

#### 4.3.2 日前 vs 实时价格预测

```text
日前参考价 p_dayah_pre(t)：
  - 目标：次日 96 点（15min）价格序列
  - 模型：LightGBM + 分位回归
  - 特征：日前可获得的全特征集
  - 蒙西语义：预出清参考价，不进入财务结算，只作运行信号

实时参考价 p_real(t)：
  - 目标：日内滚动 + 全日预测
  - 模型：LightGBM（日内）+ seasonal-naive（全日基线）
  - 特征：实时可获得特征（含最新实绩价格的滞后）
  - 蒙西语义：进入财务结算的参考价
```

#### 4.3.3 中长期价格预测

```text
月度价格分布 p_long(month)：
  - 目标：未来 1-12 月的月度价格分布（点 + 分位带）
  - 模型：季节性 naive + 趋势外推 + 月度回归
  - 特征：历史月度均价、季节项、燃料价格代理（可选）
  - 输出：月度均值 + 价格走廊 [q_0.1, q_0.9]
  - 用途：中长期头寸决策的价格输入
```

### 4.4 负荷预测增强

#### 4.4.1 多层级负荷预测

```text
层级结构（自底向上）：
  场站/用户组 → 组合 → 区域 → 节点 → 系统

预测策略：
  1. 底层预测：各场站/用户组用 LightGBM 预测
  2. 层级协调：MinT（Trace Minimization）或约束最小二乘
     - 保证 ∑(子层) = 父层
     - 协调后预测与原始预测同时保留
  3. 降级策略：历史不足时用 climatology + 明确降级标记
```

#### 4.4.2 负荷特征

```text
X_load(t)：
├── 日历：hour、day_of_week、month、is_holiday
├── 气象：temperature、cooling_degree、heating_degree
├── 历史：load(t-1d)、load(t-7d)、滚动均值
├── 价格：price(t)（弹性负荷响应，注意因果方向）
└── 事件：计划检修、特殊日（手动注入）
```

### 4.5 风光预测增强

#### 4.5.1 风电

```text
物理模型（保留）：
  P(v) = 0.5·ρ·A·Cp(v)·v³，受切入/额定/切出约束
  → 升级：Cp 曲线按真实设备参数标定，而非默认值

统计订正（v4 新增）：
  - NWP 风速 forecast → LightGBM 预测功率
  - 特征：NWP 风速/方向/温度、历史功率滞后、时段
  - 训练数据：场站实测功率 + 对应 vintage NWP
  - 输出：点预测 + 分位区间

约束：
  - 0 ≤ P ≤ P_rated
  - 夜间不强制为 0（风电）
  - 切入/切出边界正确（v_in ≤ v ≤ v_out）
```

#### 4.5.2 光伏

```text
物理模型（保留）：
  P(G, T) = P_STC · (G/G_STC) · [1 + γ·(T - T_STC)]
  → 升级：温度系数 γ 按真实组件标定

统计订正（v4 新增）：
  - NWP 辐照度/温度/云量 → LightGBM 预测功率
  - 云量特征：低云/中云/高云分层

约束：
  - 0 ≤ P ≤ P_rated
  - 夜间（太阳高度角 < 0）强制为 0
  - 逆变器限功率约束（可选）
```

### 4.6 模型注册与版本管理

```python
# forecasting/registry.py 增强（伪代码）
@dataclass
class ModelDescriptor:
    target: str              # "price" | "load" | "wind_power" | "pv_power"
    name: str                # "lightgbm_quantile_v1"
    version: str             # "2026.08.02"
    supports_quantiles: bool
    feature_requirements: list[str]
    training_data_vintage: str
    evaluation: dict         # MAE, RMSE, pinball, CRPS

class ModelRegistry:
    def register(self, descriptor: ModelDescriptor, model: ForecastModel) -> None: ...
    def resolve(self, target: str, name: str | None, version: str | None) -> ForecastModel: ...
    def list_models(self, target: str) -> list[ModelDescriptor]: ...
```

**规则**：registry 按 target 索引；调用方可指定 `name`（如 `"lightgbm_quantile"`）或留空取默认。默认模型切换必须通过配置显式声明，禁止代码内隐式切换。

## 5. 场景与风险算法增强

### 5.1 当前实现

```text
scenario/joint_builder.py：联合场景构造（canonical API，v3 D-007）
scenario/sampler.py：LHS（拉丁超立方）+ MC 采样（legacy API，v3 弃用期；删除后采样能力并入 canonical 路径）
scenario/reduction.py：Wasserstein L1 / Kantorovich 后向缩减
相关结构：简化残差相关（历史残差协方差）
```

v4 场景增强只基于 canonical API（`ScenarioSet`/`build_joint_scenarios`），不得新增对 legacy `PriceScenario`/`generate_price_scenarios` 的依赖。

### 5.2 v4 增强：相关结构

#### 5.2.1 Copula 相关结构（可选）

当前残差相关假设高斯联合分布。v4 增加 Copula 选项，允许更灵活的尾部相关建模。

```text
联合场景构造（v4）：
  Step 1：各边际预测得到点预测 μ̂_i(t) 和残差分布 F̂_i
  Step 2：选择 Copula C(u_1, ..., u_n)
    - Gaussian Copula：尾部对称，参数少（当前残差相关的推广）
    - t-Copula：尾部相关增强，适合极端价格/负荷联合事件
    - Vine Copula（R-Vine/D-Vine）：高维灵活，每对变量独立 Copula
  Step 3：采样 → Copula 逆变换 → 联合轨迹
  Step 4：Wasserstein L1 后向缩减到目标场景数

实现策略：
  - 首版实现 Gaussian + t-Copula（statsmodels/scipy 可支撑）
  - Vine Copula 作为后续增强（需评估依赖成本）
  - 通过 ScenarioConfig.copula_type 选择，默认保持残差相关
```

#### 5.2.2 极端场景注入

### 5.4 风险度量增强

当前 `optimization/risk.py` 仅实现 CVaR。v4 扩展风险度量菜单。

| 风险度量 | 定义 | 适用场景 | 状态 |
|---|---|---|---|
| CVaR（当前） | $CVaR_\alpha = VaR_\alpha + \frac{1}{1-\alpha}E[(L-VaR_\alpha)^+]$ | 尾部风险，LP 可线性化 | 已实现 |
| 最坏场景（v4） | $\max_s L_s$ 或 top-k 平均 | 极端风险厌恶，LP 可线性化 | 新增 |
| EVaR（v4 可选） | $EVaR_\alpha = \inf_{z>0} \{z \ln E[e^{L/z}] / (1-\alpha)\}$ | Chernoff 上界，凸但非线性 | 可选 |
| 机会约束（v4 可选） | $P(L \le L_{max}) \ge 1-\epsilon$ | 约束违约概率控制 | 可选 |


## 6. 优化内核增强

### 6.1 BESS 物理约束内核增强

#### 6.1.1 当前实现

#### 6.1.2 退化模型升级（v4）

```text
退化模型层级：
  Level 0（当前）：线性退化
    C_deg = deg_cost × ∑ (p_charge + p_discharge) × dt
    优点：LP 可解，简单
    缺点：不区分日历退化和循环退化

  Level 1（v4 P0）：日历 + 循环分离
    C_deg = C_calendar + C_cycle
    C_calendar = k_cal × (soc_avg / soc_max) × T        # 日历退化，与平均 SOC 和时间相关
    C_cycle = k_cyc × ∑ |ΔSOC|                            # 循环退化，与 SOC 摆幅相关
    优点：更接近真实电池退化机理
    实现：LP 可线性化（soc_avg 用积分变量，ΔSOC 用辅助变量）

  Level 2（v4 P2）：温度耦合退化
    C_deg = f(T, SOC, DOD, C-rate)
    需要：电池热模型、环境温度预测
    实现：非线性，需分段线性化或外层迭代
    状态：仅设计，不实现
```

## 7. 头寸与报价策略增强

### 7.1 中长期头寸：从启发式到约束优化

#### 7.1.1 当前实现

`positions/mid_long_planner.py`：价差 → 覆盖比例 `alpha_long` 的固定线性映射（`alpha = clip(0.7 + spread_ratio×2, 0.7, 0.9)`），无优化、无风险约束。

#### 7.1.2 v4 增强：约束优化头寸

```text
中长期头寸优化模型（v4）：

决策变量：
  q_long[m]：各月中长期合约量（MWh），m ∈ {1, ..., 12}

目标：
  min  ExpectedProcurementCost
     + λ_cvar × CVaR_α(Cost)
     + λ_turnover × ∑ |q_long[m] - q_long_prev[m]|    # 换手惩罚

其中：
  Cost[m] = q_long[m]·p_long[m] + (q_load[m] - q_long[m])·p_real[m]

约束：
  0 ≤ q_long[m] ≤ q_load[m]                           # 不可超购
  ∑_m q_long[m] ≤ annual_budget                       # 年度预算
  q_long[m] ≥ min_coverage × q_load[m]                # 最低覆盖
  q_long[m] ≤ max_coverage × q_load[m]                # 最高覆盖
  |q_long[m] - q_load[m]·target_ratio| ≤ tolerance    # 偏差容忍

输入：
  - 月度负荷预测分布（来自 forecasting）
  - 月度中长期价格分布（来自 forecasting）
  - 月度实时价格分布（来自 forecasting）
  - 预算、覆盖上下限、风险参数（来自配置）

求解：
  - 12 月 + 场景数 → LP/MILP
  - 场景来自 forecasting 的月度联合场景
  - CVaR 复用 optimization/risk.py
```

**向后兼容**：保留当前启发式作为 `MidLongStrategy="heuristic"`，新增 `MidLongStrategy="cvar_optimization"`。默认策略由配置决定。

### 7.3 报量报价策略（可选能力）

#### 7.3.1 定位

当前蒙西活动主链中，日前模块只输出运行计划，不含财务报量报价。v4 的报量报价策略作为**可选能力**实现，面向蒙西发电侧"报量报价"参与现货的场景（如新能源报量报价）。

### 9.3 风险与边界

1. **真实数据可得性**：P1/P2 多数增强依赖真实市场/场站数据。数据不可得时，对应增强降级为工程基线或推迟。
2. **蒙西规则确认**：结算回收参数和报量报价规则必须以正式文档为准。未确认前，相关功能保持 `TODO(rule-confirm)` 标记。
3. **计算复杂度**：多资源联合 + 场景 + CVaR 可能显著增加求解时间。需监控性能基准，必要时用场景缩减或 Benders 分解。
4. **无前瞻风险**：ML 预测引入更多特征，无前瞻校验必须覆盖所有新特征。forecast vintage 管理是硬约束。
5. **向后兼容**：所有增强通过配置/registry 切换，不破坏现有契约和回归基线。默认行为不变，除非显式配置。

## 10. 公共契约影响评估

v4 的算法增强对现有公共契约的影响：

| 契约 | 影响 | 处理 |
|---|---|---|
| `ForecastRequest`/`ForecastResult` | 无破坏性变更，新增 `quantiles` 实际填充 | 兼容 |
| `ScenarioSet`/`Scenario` | 无变更，增强在生成层；生成层只基于 canonical API（v3 D-007），不得依赖 legacy `PriceScenario` | 兼容 |
| `OperationalPlan` | 多资源扩展需新增资源计划字段 | 新增可选字段，默认单 BESS 行为不变 |
| `SettlementReport` | 账单对账和多产品扩展需新增分项 | 新增可选分项，默认单结算行为不变 |
| v3 配置子对象（D-003） | 新增 `RiskConfig`、`StrategyConfig`、`ResourceConfig`、`BiddingConfig` | 独立配置，不并入 v3 六子对象 |
| `MarketMode` Protocol（v3 D-002） | 报价策略作为可选注入点扩展（§7.3） | 新增可选注入点，默认单结算模式行为不变 |
| `PositionPlan` | 约束优化策略输出字段更丰富 | 新增可选字段 |
| `DecisionTrace` | 新增算法版本的追踪 | v3 D-006 后由事件链生成；v4 经事件链追加算法版本字段，不手工拼装 |

**原则**：所有变更为**新增可选字段**或**独立配置**，不删除现有字段，不改变默认行为。回归基线（366 passed）必须保持通过。
