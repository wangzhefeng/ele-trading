## 2. 版本定位

### 2.1 v3、v4、v5 的关系

| 版本 | 权威范围 | v5 处理方式 |
|---|---|---|
| v0～v2 | 原始产品需求、公式与迁移方案 | 仅用于追溯；与后续决策冲突时不作为实现或验收依据 |
| v3 | 已批准的业务不变量、领域分层、MarketMode、组合式配置、事件链与优化内核 | 继续生效；其未完成项由本文列为显式缺口，不重开已完成迁移 |
| v4 | 算法增强方向与 P0/P1/P2 路线 | P0 是既有基线；P1/P2 的未完成项在本文按当前代码重新排序 |
| v5 | 当前事实快照、概率预测、状态场景、市场仿真、参与者行为、经济验收及下一开发路线 | 当前唯一在研设计与实施路线 |

v5 不是对 v3 的替代。`market_simulation` 已按 D-014～D-016 写入 v3 决策记录并由结构守卫隔离；其标准算例实现不构成真实市场部署或生产默认切换证据。

### 2.2 核心判断

电力交易算法的最终目标不是最小化独立的预测误差，而是在决策时刻可获得的信息下，改善风险调整后的实际结算结果：

$$
\mathcal{I}_{t}
\rightarrow
P(\text{price},\text{load},\text{wind},\text{pv},\text{state}\mid\mathcal{I}_{t})
\rightarrow
\mathcal{S}_{t}
\rightarrow
a_t^{*}
\rightarrow
\text{SettlementCost}_{t}
$$

其中：

- $\mathcal{I}_{t}$ 是决策时刻可获得且可追溯的数据；
- $\mathcal{S}_{t}$ 是状态条件联合场景；
- $a_t^{*}$ 是头寸、报价、BESS、DR 和新能源联合决策；
- 最终验收对象是结算成本、收益、尾部风险和后悔值，而不是单一 MAE/RMSE。

### 2.3 范围

v5 覆盖：

1. 日前参考价、实时结算价、日前—实时价差和中长期价格分布；
2. 市场状态、供需裕度、阻塞裕度、规则版本和极端事件；
3. 负荷、风电、光伏和气象多源概率预测；
4. 状态条件 Copula、极端模板、重要性采样和对抗压力场景；
5. CVaR、最坏场景、EVaR 与机会约束；
6. 多 BESS、DR、风光限电和多产品联合优化；
7. 场景感知 MPC、实测状态反馈和执行偏差学习；
8. 中长期、月度订单簿和报量报价策略；
9. DC 网络、SCED、SCUC、LMP、阻塞、备用和 N-1 市场数字孪生；
10. 参与者行为校准、ABM 与 MARL；
11. 账单对账、多产品结算、无前瞻回测和线上退化。

### 2.4 非目标

v5 不做以下事情：

- 不用研究材料中的经验比例、阈值或省份判断替代正式市场规则；
- 不把合成数据结果写成生产收益结论；
- 不以高价本身反推“发生阻塞”，市场状态标签必须来自物理或制度证据；
- 不把 SCED/SCUC 的系统运营目标与本方交易利润目标混为同一目标函数；
- 不将 MARL 在模拟器中的高收益直接视为现实可执行收益；
- 不把 `src/investment_estimation/` 并入 `ele_trading`；长期装机和投资情景只通过版本化输入契约接入；
- 不在 v5 实施中顺手重构与上述闭环无关的模块。

## 3. 当前实现基线与缺口

### 3.1 当前代码事实

当前可回归的活动链路为：

```text
数据/规则快照与配置
  → 多价格角色预测 bundle
  → 联合场景或状态条件场景
  → 中长期/月度头寸与日前运行计划
  → 日内新 vintage 重优化
  → MarketMode 注入结算
  → 事件链、walk-forward 与基础指标
```

截至 2026-08-08，V5-0～V5-7 均已有对应代码与专项测试；全仓验证命令
`env -u PYTHONPATH UV_CACHE_DIR=.uv_cache uv run pytest -q -W error::RuntimeWarning`
结果为 **711 passed, 4 skipped, 5 deselected, 11 warnings**。该证据只覆盖接口、结构守卫、合成数据与标准算例，不是生产晋级证据。

| 能力 | 已实现事实 | 当前成熟度 |
|---|---|---|
| 数据、规则、网架证据 | `DataAvailabilityRecord`、`RuleSnapshot`、`GridSnapshot` 与反例框架 | 契约/骨架；没有真实来源目录、许可、停运和账单数据 |
| 预测语义 | `PriceRole`、多价格 `MarketForecastBundle`、按新决策时刻重签发日内 forecast vintage、可选市场状态 provider | 已接线能力；状态特征 provider、NWP 多源和生产校准缺失 |
| 场景与风险 | 状态条件 Student-t Copula、极端模板、保护缩减、worst-case/top-tail/EVaR/chance constraint | 独立算法核；无历史校准、Vine、重要性采样、对抗压力和完整物理投影 |
| 运行与结算 | 温度退化、多资源 LP、执行偏差估计、单结算账单对账 | 执行偏差已可选接入日内约束并记录诊断；多资源可选产生独立资源级计划与状态，但未进入资源级日内、计量或正式结算；对账仍未接线 |
| 报价与事件证据 | `BidSubmission`、`MarketAwardReceipt`、带关联 ID 的 Bid/Award 事件、独立 `PositionEvent`、单结算 plan-only capability | 工程链路已接线：候选报价经 capability 验证产生 BidEvent，Award 仅由回执构造；真实市场产品规则与回执适配待 V5-10 |
| 市场仿真 | DC SCED、SCUC 后定价/uplift、支路 N-1、OfferStack、Logit ABM、表格 Q-learning 与 policy guard | 标准算例原型；无真实网架/报价校准，不进入交易主链 |
| 验收与治理 | block-bootstrap、风险/对账/反例/约束门、ShadowEvaluator、`InvariantEvidence`、结算后自动对账 | 验收只接受证据对象（遗留 bool 不算正式证据）；提供 `BillingStatement` 时自动对账；仍无 archived-vintage、真实账单、影子运行、漂移或回滚演练 |

### 3.2 已解决的原始语义冲突

V5-1 已解决早期“所有价格隐式映射到 `p_real`、日前和日内复用同一 forecast vintage”的问题：市场模式声明所需价格角色，编排器按当前决策时刻构造多价格 bundle，日内重建价格、负荷、风光、状态与场景输入。该能力不等于所有真实数据源、状态特征或模型已可用。

### 3.3 当前必须完成的闭环缺口

1. **报价—成交—履约的工程语义已修复，真实市场接入仍缺失**：主链已支持候选 Bid 构造、capability 验证、BidEvent 产生与回执→Award 关联；未知 bid 的回执显式失败；但真实产品定义、申报窗口与市场回执适配器待 V5-10。
2. **算法核未成为完整运行能力**：执行偏差收紧已可选消费于日内重优化；多资源优化已可产生独立计划，但尚未消费资源级实际计量/结算；提供账单时结算后自动对账，统一验收要求证据对象；市场仿真仍未被常规交易/回测主链消费。
3. **真实证据缺失**：没有可审计的 archived-vintage 数据目录、正式规则/网架/报价/账单快照，也没有保留期校准结果。
4. **生产治理未实现**：没有 champion/challenger 持久化、漂移监控、回滚配置和影子运行证据。

后续开发不得再以新增孤立算法模块作为“阶段完成”依据；每批工作必须同时交付主链接线、失败透明、回归测试和对应硬退出证据。

## 4. v5 目标与设计原则

### 4.1 目标

| 维度 | 当前状态 | v5 目标 |
|---|---|---|
| 价格语义 | 单一通用价格 | 日前/实时/价差/中长期按 MarketMode 明确角色 |
| 概率预测 | q0.1/q0.9 LightGBM 基线 | 经校准的多分位、CRPS/PIT、状态条件分布 |
| 市场机理 | 价格历史相关 | 供需、阻塞、规则和行为共同驱动 |
| 场景尾部 | 高斯外推 | 状态条件尾部 + 历史极端 + 仿真压力场景 |
| 市场响应 | 外生价格 | SCED/SCUC + 报价响应 + ABM |
| 策略学习 | 规则/优化 | 规则、随机优化、ABM、MARL 多层策略 |
| 运行闭环 | 日前 + 单次日内重算 | 多 vintage MPC + 遥测反馈 + 执行偏差学习 |
| 验收 | 工程测试和合成算例 | 真实数据、物理复算、账单对账、经济显著性 |

### 4.2 原则

1. **因果时点优先于模型精度**：任一输入必须满足 `available_at ≤ issue_time ≤ decision_time`。
2. **市场角色先于字段名称**：`price` 必须说明是日前参考、实时结算、合同参考还是辅助信号。
3. **状态概率先于单点状态**：市场状态输出概率，不将边界附近样本硬切成唯一标签。
4. **物理引擎与交易策略解耦**：SCED/SCUC 模拟市场，交易优化消费其输出；不得把两个目标函数混成一个求解器。
5. **仿真先校准、学习后接入**：ABM 和 MARL 只能使用通过校准门的环境。
6. **真实数据门不等于延期**：数据归集、质量评估和规则确认是正式实施任务，不是范围外依赖。
7. **全量建设、分级上线**：所有阶段进入 v5，但每级生产默认必须独立验收。
8. **失败透明**：数据缺失、场景诊断失败、求解失败和模型漂移均进入事件链和退化记录。
9. **契约增补、旧行为可复现**：现有公共字段不删除；兼容期内旧入口必须产生可解释的等价结果。
10. **经济价值为最终裁决**：候选模型只有在风险调整后的结算结果改善时才能晋级。

## 6. 数据、规则与时点契约

### 6.1 数据可用性矩阵

V5-0 必须建立机器可读的数据目录，每类数据记录：

| 字段 | 含义 |
|---|---|
| `source_id` | 数据源标识 |
| `scope_type/scope_id` | 系统、区域、节点、场站、机组或参与者 |
| `event_time` | 数据描述的业务时刻 |
| `published_at` | 外部数据首次发布时刻 |
| `available_at` | 本系统实际可消费时刻 |
| `version` | 数据版本或文件哈希 |
| `revision` | 同一业务时刻的修订序号 |
| `quality_flags` | 缺失、延迟、插补、异常、模拟等标志 |
| `license/owner` | 使用边界和负责人 |

`MarketDataSnapshot.as_of` 保留，新增逐字段 `available_at` 证据。只有同时满足以下条件的数据才能进入决策：

$$
\text{published\_at} \le \text{available\_at}
\le \text{issue\_time}
\le \text{decision\_time}
$$

### 6.2 规则快照

新增 `RuleSnapshot`：

```python
@dataclass(frozen=True, slots=True)
class RuleSnapshot:
    market: str
    rule_version: str
    published_at: pd.Timestamp
    effective_from: pd.Timestamp
    effective_to: pd.Timestamp | None
    parameters: Mapping[str, object]
    source_document: str
    confirmed: bool
```

规则的“生效时刻”和“市场参与者已知时刻”必须分离。回测只能使用当时已发布的规则；当前尚未确认的规则参数在 `confirmed=False` 时不得通过正式账单验收。

### 6.3 网架和机组快照

新增 `GridSnapshot`，至少包含：

- bus、branch、reactance、thermal limit；
- generator、bus mapping、Pmin/Pmax、ramp、minimum up/down；
- startup/shutdown/no-load/variable cost；
- reserve requirement；
- planned outage 与 forced outage；
- interconnector schedule 与可用容量；
- topology version、as-of 和数据来源。

未知参数必须显式标为 `unknown` 或使用有来源的校准区间，不能静默填默认值。

### 6.4 报价与参与者数据

ABM/MARL 的最小数据面：

- 分段报价曲线和提交时刻；
- 中标量、出清价和边际状态；
- 参与者/机组映射；
- 可用容量、成本代理和运行约束；
- 规则版本和价格上下限；
- 数据匿名化映射版本。

无真实报价时，可使用 SCED/SCUC 生成成本型基准代理，但仿真成熟度只能标为“物理基线”，不得标为“行为已校准”。

## 7. 概率预测设计

### 7.1 价格角色模型

按市场模式定义价格角色：

```text
DAY_AHEAD_REFERENCE  日前参考/预出清信号
DAY_AHEAD_SETTLEMENT 日前财务结算价（双结算模式）
REAL_TIME_SETTLEMENT 实时财务结算价
SPREAD_DA_RT         实时 - 日前价差
MID_LONG_TERM        月度/年度价格分布
```

单结算模式：

- 日前价只作运行和特征信号；
- 实时价进入财务结算；
- 优化场景的核心价格目标是 `REAL_TIME_SETTLEMENT`。

双结算模式：

- 日前和实时均为结算目标；
- 联合场景必须同时包含二者及其相关性。

现有 `ForecastRequest.data` 先承载标准化 `price_role` 和 `rule_version`；待 v5 公共契约评审后再决定是否提升为显式字段，避免在 Draft 阶段破坏契约。

### 7.2 日前—实时联合预测

比较三类模型：

1. **独立模型**：分别预测 $P^{DA}$ 和 $P^{RT}$；
2. **价差模型**：

$$
\hat{P}^{RT}_{t}=\hat{P}^{DA}_{t}+\widehat{\Delta P}_{t}
$$

3. **状态条件混合模型**：

$$
P(P^{RT}_{t}\mid X_t)
=
\sum_{k\in\mathcal{K}}
\pi_k(X_t)
P_k(P^{RT}_{t}\mid X_t)
$$

其中 $\mathcal{K}=\{normal, strained, congested, extreme\}$。

模型选择不预设结论，使用相同 vintage、相同测试期和相同交易策略比较。

### 7.3 市场状态预测

新增状态 provider，输出每个时段的状态概率：

```python
@dataclass(frozen=True, slots=True)
class MarketStateForecast:
    issue_time: pd.Timestamp
    valid_time_index: pd.DatetimeIndex
    probabilities: pd.DataFrame
    state_definition_version: str
    feature_as_of: pd.Timestamp
    model_version: str
```

状态标签优先使用：

- 断面/联络线裕度；
- 备用率；
- 边际机组或稀缺资源变化；
- SCED/SCUC 约束激活；
- RUC/临时启机和故障；
- 正式发布的限电、检修和极端天气事件。

价格只用于验证状态的经济后果，不单独作为状态标签。若只有价格数据，模型名称必须标为 `price_regime_proxy`，不得宣称识别了物理阻塞。

### 7.4 特征组织

价格特征按可获得性分层：

```text
Layer 0：日历、滞后、滚动统计（当前）
Layer 1：同 vintage 的负荷、风、光、净负荷和气象
Layer 2：供需裕度、备用率、联络线/断面裕度、检修与故障
Layer 3：规则版本、价格边界、市场成熟阶段和政策事件
Layer 4：参与者报价统计、成交率、集中度和行为状态
```

每个模型 descriptor 必须声明：

- 必需特征与可选特征；
- 缺失时的退化 provider；
- 训练数据规则版本范围；
- 数据和模型版本；
- 支持的价格角色和预测时效。

### 7.5 NWP 与风光预测

v5 全量实施：

1. ECMWF、GFS、GRAPES、本地 WRF 等源通过 adapter 接入；
2. 每个源保留 issue time、lead time 和模型版本；
3. 按场站、季节和预测时效学习源权重；
4. 风电执行轮毂高度订正、风向和功率曲线标定；
5. 光伏执行辐照度、组件温度、云量、太阳高度角和逆变器约束；
6. 点预测、分位预测和校准后区间同时输出；
7. 气象源切换必须由滚动验证驱动，不按单一历史窗口永久固定。

### 7.6 中长期价格走廊

中长期模型输出月度联合分布，而非单一均价：

- 负荷增长情景；
- 新增装机和退役情景；
- 燃料、碳和跨区送受电情景；
- 市场规则版本；
- 典型年气象；
- 价格均值、q0.1/q0.5/q0.9 和极端区间。

`investment_estimation` 只通过版本化情景文件向 forecasting 提供装机/成本输入，不反向依赖交易包。

### 7.7 概率校准

所有概率模型至少比较：

- 直接分位回归；
- 残差分位；
- split conformal；
- 按市场状态分层的 conformal。

评估包括 Pinball Loss、CRPS、PIT、区间覆盖率、尖峰事件 Brier Score 和状态条件校准。

## 8. 状态条件场景与风险

### 8.1 新场景构造流程

```text
Step 1：采样市场状态 k ~ Categorical(π_state)
Step 2：从状态 k 的各边际分布采样 DA/RT/负荷/风/光
Step 3：用状态条件 Copula 注入跨目标、跨时段依赖
Step 4：混入历史极端事件模板
Step 5：用重要性采样补足临界区域
Step 6：用对抗搜索生成最大损失压力场景
Step 7：执行物理可行性投影
Step 8：缩减并强制保留关键峰值、爬坡、阻塞和损失场景
Step 9：诊断通过后进入优化
```

### 8.2 Copula 路线

- Gaussian Copula：保留为基线和退化路径；
- t-Copula：v5 状态条件场景的主候选；
- Vine Copula：纳入离线基准，但只有在高维样本量和验证收益足够时才能成为默认；
- Copula 必须同时支持 target-level 和 target-time 依赖；
- 参数按训练窗口与市场状态拟合，不能使用测试期实际值。

### 8.3 极端模板

模板来源必须可追踪：

- 高负荷 + 低风光；
- 风光快速下跌；
- 联络线降容或检修；
- 机组故障；
- 低备用 + 高报价；
- 极端温度；
- 规则切换日；
- 负价或价格上限事件。

每个模板记录：事件日期、当时可见信息、实际轨迹、状态标签、规则版本和物理证据。模板扰动后必须通过功率平衡、容量、爬坡和价格边界检查。

注入概率由历史频率、贝叶斯平滑或仿真暴露频率标定，不采用研究文档中的固定经验比例。

### 8.4 重要性采样与对抗压力场景

重要性采样重点覆盖：

- 阻塞裕度接近零；
- 备用率接近规则阈值；
- SOC 接近边界；
- DR 履约临界；
- 偏差考核分段点；
- 价格上限和负价边界。

对抗场景求解：

$$
\max_{\xi\in\Xi} L(a^{*}(\xi),\xi)
$$

其中不确定集 $\Xi$ 必须由历史支持集、物理边界和规则边界共同定义。对抗场景不赋予经验概率，只作为稳健性压力测试或最坏场景项。

### 8.5 场景诊断升级

在现有诊断上增加：

- 状态概率守恒；
- DA/RT 价差边际一致性；
- 上下尾依赖；
- 跨时段自相关和爬坡分布；
- 尖峰持续时长；
- 关键约束激活率；
- 对抗场景与概率场景分区标识；
- 缩减前后 tail loss、CVaR 和关键事件保持。

任何硬诊断失败时，场景集不得进入下游优化。

### 8.6 风险度量菜单

v5 实施：

| 风险度量 | 用途 | 实现约束 |
|---|---|---|
| CVaR | 主要尾部风险度量 | 复用当前线性化 |
| Worst-case / Top-k | 极端稳健性 | 线性辅助变量 |
| EVaR | 指数尾部上界 | 需要凸求解能力或外层近似 |
| Chance Constraint | SOC、履约、偏差等违约概率 | 场景布尔变量或安全近似 |
| Distributionally Robust | 分布漂移 | 仅在 Wasserstein 半径可由验证数据标定后启用 |

同一策略不得通过同时调节场景概率和风险参数重复放大或缩小风险。

## 9. 市场数字孪生：SCED 与 SCUC

### 9.1 定位

数字孪生解决三个问题：

1. 给定负荷、可再生、网架和报价，市场如何出清；
2. 哪些约束产生价格跳变和空间价差；
3. 本方报价变化如何影响成交量、出清价和风险。

它不是生产调度系统，不替代交易中心，也不为缺失的真实数据提供“伪真值”。

### 9.2 DC 网络模型

首版采用 DC power flow：

$$
f_{ij,t}=B_{ij}(\theta_{i,t}-\theta_{j,t})
$$

$$
-F_{ij}^{max}\le f_{ij,t}\le F_{ij}^{max}
$$

节点功率平衡：

$$
\sum_{g\in G_i}p_{g,t}+r_{i,t}+s^{shed}_{i,t}
-d_{i,t}
=\sum_{j}f_{ij,t}
$$

需要明确：DC 模型不能表达无功、电压和 AC 可行性。若业务需要节点级安全验证，AC power flow 只作为离线复核，不进入首版市场出清。

### 9.3 SCED

SCED 目标：

$$
\min
\sum_{g,t} C_g(p_{g,t})
+VOLL\sum_{i,t}s^{shed}_{i,t}
+C_{curt}\sum_{i,t}s^{curt}_{i,t}
$$

约束包括：

- 节点功率平衡；
- 机组 Pmin/Pmax；
- 爬坡；
- 线路限额；
- 可再生可用出力和限电；
- 备用；
- 联络线计划或优化边界；
- 价格上下限对应的报价规则。

SCED 首先在无整数变量的标准算例上验证，输出：

- 机组出力；
- 线路潮流；
- 负荷损失和限电；
- 约束激活集；
- 节点边际价格；
- 拥塞租金和备用价格。

### 9.4 SCUC

SCUC 在 SCED 上增加：

- 开停机二元变量；
- 启停成本和空载成本；
- 最小开停机时间；
- 启停轨迹；
- 多时段爬坡；
- 备用联动；
- N-1 安全约束或预生成 contingency cuts。

开发基线使用 PuLP + CBC；若标准算例性能不满足预算，再通过现有 solver adapter 接入更强求解器。不得在没有实测性能证据时提前增加全局依赖。

### 9.5 SCUC 后定价

MILP 的对偶值不能直接作为可解释 LMP。v5 采用：

1. 求解 SCUC 得到 commitment；
2. 固定整数开停机状态；
3. 重跑连续 SCED；
4. 读取节点平衡约束对偶作为能量 LMP；
5. 单独计算启停/空载导致的 uplift，不混入 LMP。

此方法仍不是所有市场的正式定价规则，最终必须由目标市场规则快照确认。

### 9.6 联络线与阻塞

联络线支持两种模式：

- `FIXED_SCHEDULE`：作为边界注入；
- `OPTIMIZED_FLOW`：作为跨区优化变量。

阻塞特征使用：

$$
Margin_{l,t}=\frac{F_l^{max}-|f_{l,t}|}{F_l^{max}}
$$

但不得将联络线视为唯一价格驱动。负荷、机组组合、备用、故障、爬坡、报价和其他断面同时进入解释。

### 9.7 N-1 与安全校验

N-1 实施顺序：

1. 基础线路/机组 outage 场景枚举；
2. PTDF/LODF 快速筛选；
3. 对关键事故加入显式约束；
4. 输出每个 contingency 的不可行、负荷损失和价格变化；
5. 只对规则要求的安全集计入正式出清。

### 9.8 校准层

数字孪生校准目标不是逐点拟合价格，而是同时匹配：

- 机组出力和启停；
- 线路/断面是否拥塞；
- 系统和节点价格；
- 限电、负荷损失和备用；
- 出清量与边际机组；
- 极端事件持续时间。

参数校准必须分训练期和保留期；不能在测试事件上调参数后再宣称复现成功。

## 10. 报价、ABM 与 MARL

### 10.1 报量报价契约

新增 `positions/bidding/`：

```python
@dataclass(frozen=True, slots=True)
class BidSegment:
    quantity_mwh: float
    price_yuan_mwh: float
    irrevocable: bool = False

@dataclass(frozen=True, slots=True)
class BidSubmission:
    participant_id: str
    target_market: str
    delivery_index: pd.DatetimeIndex
    segments_by_period: Mapping[pd.Timestamp, tuple[BidSegment, ...]]
    issue_time: pd.Timestamp
    strategy_version: str
```

策略层级：

1. 边际成本/机会成本报价；
2. 场景最优报价；
3. 基于成交概率的 logit 报价；
4. ABM 最佳响应；
5. MARL 策略。

所有报价必须通过 MarketMode 的数量、价格、段数、时限和资源可用性校验。

### 10.2 参与者行为模型

ABM 不使用无法观测的“情绪”作为直接输入，而以可校准行为参数表达：

- 成本加成；
- 风险厌恶；
- 容量持留；
- 对历史成交率的学习；
- 对公开价格和竞争者行为的滞后响应；
- 集中度和参与者规模；
- 报价相关性和分布收缩；
- 规则变化后的策略重置。

参与者类型：

```text
CostBasedAgent
RiskAdjustedAgent
AdaptiveMarkupAgent
CapacityWithholdingAgent
FollowerAgent
PortfolioAgent
```

每个类型必须对应可识别参数和校准数据，不能只用叙事命名。

### 10.3 ABM 执行流程

```text
规则快照 + GridSnapshot + 参与者状态
  → 各 agent 生成分段报价
  → SCUC/SCED 出清
  → Award / Price / Profit / Constraint Evidence
  → agent 更新信念和策略参数
  → 重复多日或多轮
```

ABM 验收对象：

- 报价分布；
- 成交概率；
- 价格和尖峰频率；
- 市场集中度与价格加成关系；
- 策略稳定性；
- 保留期参与者行为复现。

“多轮后不报错”或“策略收敛”不构成业务验收。

### 10.4 MARL 环境

环境状态仅包含参与者当时可获得的信息：

- 自身资源状态和成本；
- 公开的负荷、风光和价格预测；
- 历史成交与公开市场状态；
- 规则和价格边界；
- 允许公开的网架/约束代理。

动作：按规则约束的分段报价参数。奖励：

$$
R_i=
Revenue_i-Cost_i
-\lambda_{risk}Risk_i
-\lambda_{violation}Violation_i
-\lambda_{turnover}Turnover_i
$$

禁止将真实未来出清结果、其他参与者私有报价或测试期状态放入训练状态。

### 10.5 MARL 训练序列

1. 单 agent 固定对手，验证环境和奖励；
2. 多 agent 同质策略，验证稳定性；
3. 异质 agent 和不同资源；
4. 规则随机化、负荷/新能源随机化和 domain randomization；
5. 对未见规则、未见极端状态和未见对手进行 out-of-distribution 测试；
6. 与边际成本、场景最优和 ABM 最佳响应基线比较；
7. 通过 policy guard 后进入影子回测；
8. 只有 V5-7 全链验收后，才允许 MarketMode 显式启用。

### 10.6 策略安全与模拟器漏洞

`policy_guard.py` 检查：

- 报价范围、段数和资源可行性；
- 规则硬约束；
- 不可解释的大幅策略跳变；
- 对模拟器参数微扰的收益敏感性；
- 训练环境与保留环境收益差；
- 是否通过未建模漏洞获利；
- 是否出现无成交但虚增 reward 等记账错误。

任何策略若在物理复算、账单复算或环境微扰后收益消失，判为 simulator exploitation，不得晋级。

## 11. 多资源优化、头寸与结算

### 11.1 多资源联合优化

首个完整资源组合：

- 多台 BESS；
- 可调负荷/DR；
- 风电和光伏限电；
- 电网购售电；
- 中长期和月度头寸；
- 可选备用/调频产品。

目标：

$$
\min
E[C_{energy}+C_{contract}+C_{deviation}+C_{degradation}
+C_{DR}+C_{curtailment}-R_{ancillary}]
+\lambda\rho(L)
$$

其中 $\rho$ 可为 CVaR、EVaR、worst-case 或组合。

### 11.2 Level 2 温度退化

Level 2 使用温度、SOC、DOD 和 C-rate：

$$
C_{deg}=f(T,SOC,DOD,C\text{-rate})
$$

实施方式：

1. 先建立离线退化核和真实/厂商参数校准；
2. 对运行区间做二维或多维分段线性化；
3. 将分段成本作为优化目标组件；
4. 与 Level 0/1 比较收益、吞吐量、寿命和求解时间；
5. 若非线性误差或求解时间超预算，退化到 Level 1。

### 11.3 场景感知 MPC 与状态反馈

日内每次滚动都执行：

```text
新 decision_time
  → 拉取最新 MarketDataSnapshot / telemetry
  → 生成新 ForecastBundle
  → 重建状态条件 ScenarioSet
  → 冻结已执行前缀
  → 以实测 SOC、功率和履约状态作为新初值
  → 求解剩余窗口
  → 只执行下一时段
```

执行偏差模型学习：

- SOC 估计偏差；
- 指令与实测功率偏差；
- 响应延迟；
- 可用容量和效率漂移；
- DR 实际履约概率。

这些偏差进入下一窗口约束收紧和场景分布，而不是只写日志。

### 11.4 中长期与月度头寸

v4 已实现的 CVaR 中长期优化扩展为：

- 月度负荷、实时价格和中长期价格联合场景；
- 规则版本和预算；
- 覆盖上下限、换手、信用和集中度；
- 规则变化压力场景；
- 与短期 BESS/DR 价值的边界协调。

月度出清概率按顺序升级：

```text
uniform/linear 基线
→ 历史 logit
→ 订单簿成交模型
→ ABM 出清概率
→ MARL 策略
```

### 11.5 多产品结算与账单对账

结算扩展：

- 电能量；
- 中长期合同差价；
- 月度回收；
- 偏差考核；
- DR；
- BESS 退化；
- 调频、备用等辅助服务；
- uplift 或市场专属调整项。

每个分项必须有唯一计费归属。新增对账结果：

```python
@dataclass(frozen=True, slots=True)
class ReconciliationReport:
    statement_version: str
    modeled_total: float
    billed_total: float
    differences: tuple[ReconciliationDifference, ...]
    passed: bool
```

模式专属对账编排放在 `markets/<mode>/reconciliation.py`；跨模式共享的差异契约和归因工具放在 `markets/shared.py`。结算公式仍由 MarketMode 插件拥有，不能下沉到通用 backtest 层。

差异分类：规则、参数、数据、计量、舍入、时间边界和未知。未知差异不能被并入“执行调整”后隐藏。

## 12. 回测、经济验收与线上闭环

### 12.1 回测层级

| 层级 | 价格来源 | 用途 |
|---|---|---|
| E0 | 历史实际价格，策略为价格接受者 | 预测和资源优化基线 |
| E1 | 历史订单簿/成交回放 | 报价成交验证 |
| E2 | 校准 SCED/SCUC | 物理反事实和阻塞分析 |
| E3 | SCED/SCUC + ABM | 对手响应和策略博弈 |
| E4 | 随机化环境 + MARL | 学习策略鲁棒性 |

任何高层级结果都必须同时报告低层级基线，避免将环境复杂度误当作策略增益。

### 12.2 数据切分

至少采用：

```text
训练期：模型拟合与仿真参数校准
验证期：超参数、场景阈值和风险参数选择
测试期：一次性最终评估
压力期：历史极端 + 仿真反事实，不用于参数拟合
```

规则变化时执行双重切分：时间切分 + 规则版本切分。跨规则训练必须将规则版本作为显式特征，并单独报告迁移效果。

### 12.3 预测指标

- MAE、RMSE；
- Pinball Loss、CRPS；
- PIT 和分位覆盖；
- 方向准确率和时段排序；
- 尖峰 precision、recall、F1、提前量和持续时长误差；
- 状态概率 Brier Score；
- normal/strained/congested/extreme 分层指标；
- DA/RT 价差指标。

### 12.4 场景与物理指标

- 边际分布和相关保持；
- 上下尾依赖；
- 极端事件覆盖；
- 缩减漂移；
- 场景内约束违约率；
- SCED/SCUC 功率平衡、潮流、备用和 commitment 复算；
- LMP、拥塞租金和 uplift 分解；
- 标准算例与历史保留期复现。

### 12.5 交易指标

- 实际结算成本/收益；
- 相对无策略、当前策略和 oracle 的差值；
- regret：

$$
Regret=C_{strategy}-C_{oracle}
$$

- 价格捕获率；
- 偏差考核成本占比；
- CVaR、最大回撤和最坏日；
- 退化成本、EFC、RTE；
- 履约、SOC 和市场约束违约；
- fallback 使用率；
- 计算时间和超时率。

### 12.6 模型晋级统计门

候选模型相对基线必须满足：

1. 测试期平均结算成本差 $\Delta C=C_{candidate}-C_{baseline}$ 的单侧 95% block-bootstrap 置信区间上界小于 0；
2. 测试期 CVaR 不高于基线；
3. 极端状态下的平均损失和最坏日均不恶化；
4. 概率覆盖误差不超过有限样本置信界加 0.02 容忍带；
5. 任一物理、规则、无前瞻或账单硬检查不得失败；
6. 改善不能只来自单一极端日，必须报告 leave-one-event-out 结果。

如果样本量不足以形成统计结论，成熟度只能为“实验性”，但实施阶段不取消：继续执行数据归集和影子运行。

### 12.7 Champion/Challenger

线上同时保存：

- champion 当前默认；
- challenger 新模型；
- baseline seasonal-naive/规则策略；
- oracle 仅离线；
- 每次决策的输入、模型、场景、求解和 fallback 版本。

漂移监控：

- 输入分布；
- 残差和覆盖率；
- 状态概率；
- 尖峰遗漏；
- 求解器状态；
- 实际结算与预测风险偏差；
- 仿真与真实市场差异。

### 12.8 业务反例库

新增 `backtest/counterexamples.py`，把“指标看起来较好但业务不可接受”的情况建成 HARD 测试，而不是散落在测试说明中。

基础反例：

- 偏差超过规则边界；
- SOC、功率、爬坡或履约约束越界；
- 求解失败后返回零计划或伪成功；
- forecast vintage、规则版本或数据发布时点造成前瞻；
- 单/双结算模式使用错误价格角色；
- 场景诊断失败后仍进入优化；
- SCUC 未固定 commitment 就读取 MILP 对偶作为 LMP；
- ABM 未经行为校准却输出“策略收益”；
- MARL 利用模拟器记账或物理漏洞获利；
- 账单未知差异被归入其他分项后隐藏。

统一输出：

```python
@dataclass(frozen=True, slots=True)
class CounterexampleResult:
    name: str
    passed: bool
    severity: str
    evidence: Mapping[str, object]
```

V5-0 建立注册和报告框架；V5-1~V5-6 每阶段同步增加本阶段反例；V5-7 要求所有 HARD 反例通过。任一 HARD 反例失败，整个回测报告判为不通过，不允许用平均收益抵消。

### 14.3 V5-8：报价—成交—履约证据链（工程链路已完成，真实市场接入待 V5-10）

**目标**：补齐 v3 D-006 与 v4/v5 报价能力之间的断点，使交易决策能够从报价、成交到执行和结算完整追溯。

**实施内容**：

- 已在 `domain` 增加市场无关、版本化的 `BidSubmission` 与 Bid/Award 关联标识；
- 已将 `PositionState` 与 `AwardEvent` 分离：合同/仓位作为 `PositionEvent` 进入 trace，普通 Award 必须关联 Bid 或显式外部成交引用；
- 已扩展单结算的可选报价 capability，显式声明为“仅运行计划”；
- 已将 `BidEvent` 纳入 `TradingOrchestrator` 事件链：候选报价由注入的 builder 构造、经 capability 验证后才产生 BidEvent；`AwardEvent` 仅由 `MarketAwardReceipt` 构造，引用未知 bid 的回执显式失败；
- 待为已确认产品实现真实报价 capability 与市场回执适配器（V5-10），明确是否允许报量、报价、撤改；
- 将 `market_simulation.bidding.OfferStack` 保持为仿真机组报价契约，不冒充交易侧申报；
- 已为单结算保留“仅运行计划”的显式退化路径；双结算未确认产品能力仍须显式失败；
- 新增 Bid→Award→Dispatch→Settlement 的事件、版本、规则与资源可行性测试。

**硬退出条件**：任何正式候选报价都可追溯到 forecast/规则/资源/策略版本；不能报价的市场模式有显式原因；任何 Award 必须关联 Bid 或可审计的外部成交引用；不存在无 Award 依据的正式履约计划。

### 14.4 V5-9：运行主链接线与失败透明

**目标**：把既有算法核变成受控运行能力，而不是仅由专项测试调用。

**实施内容**：

- 已将执行偏差统计可选接入日内滚动，作用于下一窗口的功率降额和 SOC 储备，并在 trace 记录样本量与收紧量；
- 多资源求解已在不可行时返回 `SolveStatus` 与空计划，并可由编排器产出独立资源级计划；待接入资源级日内、实际计量、物理 fallback 与正式结算；
- 将场景诊断、数据切分、forecast vintage 与反例检查置为回测强制门；
- 对账已在提供 `BillingStatement` 时自动消费结算报告分项（`confirmed=False` 永不通过）；统一验收已改为只接受 `InvariantEvidence`，不再接受调用方申报的布尔标志；
- 明确单结算、双结算和无报价模式的 capability/fallback 矩阵。

**硬退出条件**：正常与失败路径均有端到端测试；fallback 物理可行且被记录；每次回测自动拒绝前瞻、场景诊断失败或 HARD 反例失败的候选结果。

### 14.5 V5-10：真实数据、规则与校准

**目标**：建立从“可运行基线”升级到“可检验候选策略”所需的真实证据，不把合成算例当作校准结果。

**实施内容**：

- 建立 archived-vintage 数据目录，覆盖价格、负荷、风光、气象、规则、网架、报价、成交、计量和账单的发布时刻、可用时刻、版本、责任和许可；
- 接入至少一个真实市场模式的 RuleSnapshot、GridSnapshot 和正式账单分项；
- 实现状态特征 data provider、NWP source/vintage 管理与风光物理/统计校准；
- 在预注册保留期校准状态条件场景、退化参数、SCED/SCUC 和 ABM 行为参数；
- 将未识别参数保留为区间/情景，禁止以单点估计伪装真实市场事实。

**硬退出条件**：每个校准结论可复现到数据和规则版本；训练、验证、保留期严格隔离；模型、仿真和对账均能报告缺失证据而非默认通过。

### 14.6 V5-11：经济验收、影子运行与默认晋级

**目标**：以真实结算、尾部风险和稳定性决定候选策略是否可以改变默认，而不是用单项模型指标或模拟收益决定。

**硬退出条件**：统计、物理、规则、经济、风险、性能与回滚门全部通过；影子运行无未解释账单差异；人工 review 批准并保存可执行回滚配置。

## 15. 验证与性能预算

### 15.1 验证层级

```text
单元测试
→ 契约/结构守卫
→ 数学小算例
→ 标准电网算例
→ 历史保留期复现
→ archived-vintage walk-forward
→ 影子结算对账
→ 生产默认切换
```

不得用较低层测试替代较高层验收。例如 SCED 单元测试通过不能证明历史价格复现，MARL reward 上升不能证明结算收益改善。

### 15.2 HARD 验收

- 无前瞻校验零违规；
- 时间、单位和 price role 全部明确；
- 场景概率和版本守恒；
- 功率平衡和资源物理约束零违规；
- SCED/SCUC 标准算例复算通过；
- 结算分项唯一计费；
- 回测结果可由输入版本、规则版本、模型版本、场景 seed 和 solver 复现；
- 候选默认通过 §12.6 的经济统计门；
- 失败/超时进入显式退化，不返回伪成功。

### 15.3 性能预算

现有 v3/v4 预算继续有效。v5 新增预算在 V5-0 使用标准开发机实测后冻结，至少覆盖：

| 任务 | 预算口径 |
|---|---|
| 日前 96 点全预测 bundle | 单次 wall-clock 和内存 |
| 状态条件场景生成与缩减 | 原始/保留场景数、wall-clock、诊断时间 |
| 多资源场景优化 | 资源数×场景数×时段数 |
| SCED | bus/branch/generator 数与时段数 |
| SCUC | generator×时段×contingency，MIP gap 与超时率 |
| ABM | agent×轮次×场景，吞吐率 |
| MARL | environment steps/s、训练总时长、推理延迟 |
| 30 日 walk-forward | 全链 wall-clock、峰值内存和失败率 |

生产在线链不直接等待大规模 SCUC/ABM/MARL 训练；它消费预先校准的模型和策略。实时推理超时必须退化。

## 16. 失败、退化与治理

### 16.1 分级退化

```text
报价策略：MARL
  → ABM/场景最优
  → logit/边际成本
  → 不主动报价或外生价格模式

价格模型：状态条件联合模型
  → 日前+价差模型
  → 当前 LightGBM
  → seasonal-naive

场景模型：状态条件 t-Copula + 极端模板
  → Gaussian Copula
  → 当前联合场景
  → 确定性点预测

优化：多资源风险优化
  → 单 BESS CVaR
  → 确定性计划
  → 物理裁剪的前一可行计划

市场响应：SCUC + ABM
  → SCED
  → 历史订单簿回放
  → 外生价格
```

### 16.2 退化触发

- 数据源延迟或缺失；
- feature vintage 不合法；
- 状态模型低置信；
- 场景硬诊断失败；
- 求解超时/不可行；
- 仿真校准漂移；
- MARL policy guard 失败；
- 账单差异超限；
- 线上经济指标持续劣化。

每次退化记录：触发原因、上一级模型、实际使用模型、输入版本、时间和恢复条件。

### 16.3 治理

- 市场规则必须有正式来源和确认状态；
- 参与者数据必须匿名化并限制用途；
- MARL 策略必须保留可复算的报价输入和输出；
- 仿真结果必须标明物理基线、行为已校准或生产已验证等成熟度；
- 任何生产默认变化必须经过人工 review，不由训练脚本自动发布；
- 本文不构成自动实施或自动切换生产默认的授权。

| D-011 | 市场模拟器类型 | SCED → SCUC → ABM 全部实施，非二选一 | 必须新增独立包和大量网架/报价数据 |
| D-012 | Copula 类型 | Gaussian 为退化；状态条件 t-Copula 为主候选；Vine 纳入离线比较 | 默认选择由尾部验证决定，不凭复杂度决定 |
| D-013 | 多资源首批组合 | 多 BESS + DR + 风 + 光 + 电网 + 头寸完整实施 | 资源配置和求解规模显著增加 |
| D-014 | 市场仿真包边界 | 新增顶层 `market_simulation`，不放入 `backtest` | v5 通过后必须同步回填 v3 架构决策 |
| D-015 | MARL 定位 | 进入正式实施序列 V5-6，并要求 OOD、policy guard 和影子验收 | 不允许从模拟训练直接跳到生产默认 |
| D-016 | 实施与上线关系 | 全量建设立即进入路线；生产默认按分级门独立晋级 | 数据门是正式交付，不是延期或跳过理由 |

## 18. 研究材料取舍矩阵

| 研究命题 | v5 采用方式 | 明确拒绝的部分 |
|---|---|---|
| 日前与实时价格不同 | 建立价格角色、独立/价差/状态条件模型 | 不默认日前一定是实时可靠锚 |
| 价格存在状态跳变 | 建立物理状态概率和混合模型 | 不把高价直接等同阻塞 |
| 阻塞裕度重要 | 作为可解释物理特征和压力维度 | 不把联络线视为唯一价格驱动 |
| 基准价+残差 | 作为候选模型 | 不使用“已开机机组最低边际成本”错误公式 |
| 极端事件模板 | 纳入场景正式实施 | 不使用无依据的固定注入概率 |
| SCED/SCUC | 建立数字孪生和标准算例校准 | 不宣称替代真实交易中心 |
| 市场情绪/从众 | 转化为报价分布、滞后、相关和集中度等可观测行为特征 | 不使用无法验证的心理变量和固定参与者比例 |
| ABM | 用于对手响应和多轮市场仿真 | 不以“能收敛”替代保留期校准 |
| MARL | 在校准环境中学习和做反事实推演 | 不将模拟收益直接视为现实收益 |
| 气象源寻优 | 按场站、季节和 lead time 学习组合权重 | 不永久固定单一最佳气象源 |
| 制度周期 | 建立 RuleSnapshot 和规则版本切分 | 不把研究材料的制度判断直接写入规则参数 |
| 长期装机与政策 | 作为中长期价格情景输入 | 不把 investment_estimation 并入交易包 |
